# WHAT THE LAB

연구자와 AI 전문가가 서로를 발견하고, 협업을 확정한 뒤, 마일스톤·종료·평가까지 이어 갈 수 있도록 돕는 연구 협업 플랫폼입니다.

> 현재 저장소는 **초기 모노레포 구조와 협업 규칙을 준비한 단계**입니다. 프론트엔드·백엔드 애플리케이션 코드는 아직 생성하지 않았습니다.

## MVP가 검증하려는 것

> 연구자와 AI 전문가가 공개 모집 또는 직접 요청으로 만나 실제 프로젝트를 시작하고, 협업을 완료할 수 있는가?

핵심 흐름은 다음과 같습니다.

```text
탐색 → 협업 요청/참여 신청 → 협의·선택 → 프로젝트 확정
     → 마일스톤 → 종료 → 양방향 평가
```

상세 범위는 [docs/MVP_SCOPE.md](docs/MVP_SCOPE.md)를 기준으로 판단합니다.

## 모노레포 구조

| 경로 | 역할 |
|---|---|
| `frontend/` | Next.js + TypeScript + Tailwind CSS 웹 화면 |
| `backend/` | FastAPI API와 비즈니스 규칙 |
| `database/` | PostgreSQL/Supabase 스키마·마이그레이션·시드 |
| `ai/` | 향후 규칙 기반 추천 실험. 현재 MVP 기능 구현 대상 아님 |
| `data/` | 비식별 샘플·테스트 데이터와 데이터 설명 |
| `design/` | Figma 전달 자료와 디자인 자산 |
| `docs/` | 제품 범위, 화면, 의사결정, 협업 문서 |
| `tests/` | 저장소 공통 테스트와 E2E 테스트 |
| `infra/` | 개발·배포 환경 설정. 비밀값은 저장하지 않음 |
| `.github/` | Pull Request 등 GitHub 협업 설정 |

각 폴더의 구체적인 책임과 금지 사항은 해당 폴더의 `README.md`를 확인해 주세요.

## 3인 역할

| 담당 | 주 책임 | 현재 범위 |
|---|---|---|
| 차용우 | 통합, `main`/`develop` 관리, 메인 화면, 인증 | 공통 계약과 PR 최종 확인 |
| 장반석 | 공통 UI, 레이아웃, 디자인 시스템 | 인사이트는 MVP+ 승인 후 구현 |
| 안홍진 | AI 전문가 목록·상세, 관련 샘플 데이터 | 작은 단위의 `feature/*` 브랜치로 진행 |

역할은 소유권을 분명히 하기 위한 기준이며, 다른 영역을 수정할 때는 담당자와 먼저 인터페이스를 맞춥니다.

## Git 브랜치 규칙

- `main`: 시연·배포 가능한 안정 브랜치
- `develop`: 기능을 모아 통합 검증하는 개발 브랜치
- `feature/*`: 한 가지 기능을 작업하는 짧은 브랜치

`dev`라는 폴더를 별도로 만들지 않습니다. **브랜치 `develop`**은 코드 통합 흐름이고, **개발 환경(development environment)**은 로컬 실행 설정을 뜻합니다. 둘은 서로 다른 개념입니다.

자세한 작업 순서는 [docs/TEAM_WORKFLOW.md](docs/TEAM_WORKFLOW.md)를 따릅니다.

## 시작하기

원격 저장소를 처음 받는 팀원은 다음 순서로 시작합니다.

```powershell
git clone https://github.com/Lab-with-Al-platform/what_the-lab.git
cd what_the-lab
git switch develop
Copy-Item .env.example .env
```

`.env`에는 각자의 로컬 값만 입력하고 Git에 올리지 않습니다. 프론트엔드와 백엔드 설치·실행 명령은 실제 앱 골격이 생성될 때 각 폴더 README에 추가합니다.

## 문서 우선순위

결정이 충돌하면 다음 순서로 확인합니다.

1. 최신 팀 합의와 `docs/03_DECISION_LOG.md`
2. `docs/MVP_SCOPE.md`
3. `docs/02_SCREEN_GUIDE.md`
4. 기타 기획·시장조사 자료

시장조사 제안이나 미래 아이디어는 자동으로 MVP가 되지 않습니다. 범위를 바꾸려면 팀 합의와 문서 수정이 먼저입니다.

## 보안 원칙

- `.env`, API 키, Supabase 서비스 역할 키를 커밋하지 않습니다.
- 연구 원자료나 개인 연락처를 저장소에 넣지 않습니다.
- 공개 API 응답에는 권한 확인 전 개인 연락처를 포함하지 않습니다.
- 샘플 데이터는 가상·비식별 데이터만 사용합니다.
