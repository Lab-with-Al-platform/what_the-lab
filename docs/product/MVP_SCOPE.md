[저장·확인 경계](../qa/insight-catalog-20261022/README.md).

> 같은 날 후속 합의: 기본 전체 목록과 수집후보/게시글/자동수집 설정 사이드바, 통합 필터 목록, 편집·실제 기사 구성 미리보기 모달을 구현합니다. 수집 설정은 팀 공통 DB **저장만**, 수집·예약 실행은 다음 단계입니다. 공개 원고는 수정 중 유지하고 별도 수정 판본을 재검토·재승인한 후 명시적 공개 API 반영을 지원합니다. 일반 공개 사이트의 정적 원고 DB 전환·트렌드 전용 승인 검증·실제 글 승인/교체·운영 배포는 실행하지 않습니다. [현재 동작·검증](../qa/insight-workspace-20261022/README.md).

## 1. 목적

MVP의 질문은 다음 한 문장입니다.

> 연구자와 AI 전문가가 플랫폼에서 서로를 발견하고, 실제 프로젝트를 시작하여, 협업을 끝낼 수 있는가?

검색 화면만 동작하거나 요청만 보낼 수 있는 상태는 MVP 완료가 아닙니다. 아래 흐름 중 하나로 시작한 협업이 종료와 평가까지 이어져야 합니다.

```text
공개 모집: 프로젝트 등록 → 전문가 참여 신청 → 검토·협의 → 프로젝트 확정
직접 요청: 전문가 탐색 → 연구자 협업 요청 → 검토·협의 → 프로젝트 확정

공통 흐름: 프로젝트 확정 → 마일스톤 → 종료 → 양방향 평가
```

## 2. MVP에 포함

### 계정과 프로필

- 회원가입·로그인
- 한 계정에서 연구자/AI 전문가 역할 구분
- 연구자 프로필과 AI 전문가 프로필

### 탐색과 매칭

- 프로젝트 등록·수정과 과업 템플릿
- 프로젝트 목록·상세
- AI 전문가 목록·상세
- 연구자 → 전문가 `협업 요청`
- 전문가 → 공개 프로젝트 `참여 신청`
- 요청·신청 검토, 협의, 수락·거절·선택

### 협업 진행

- 프로젝트 확정과 프로젝트 멤버 권한
- 마일스톤 생성·담당·기한·완료 조건·검토
- 사이트 알림함
- 프로젝트 종료
- 완료 프로젝트 기반 양방향 평가

### 연구 협업 특화 정보

- Data Readiness 핵심 필드
- 공개/일부 공개/비공개 최소 구분
- 데이터 접근, NDA, IRB 관련 최소 메타데이터
- 보상 형태 표시(거래 중개는 제외)
- 최소 관리자 기능

## 3. MVP에서 제외

다음 기능은 폴더나 문서가 있더라도 현재 구현하지 않습니다.

- 관심 프로젝트·전문가 저장
- 고급 Availability 필터와 이력
- 내부 일정·외부 캘린더 연동
- 학교·기관 및 외부 경력 인증
- 공개 Research AI Portfolio 고도화
- 규칙 기반/개인화 AI 추천
- 운영형 인사이트 화면과 AI 블로그 자동 생성
- 실시간 DM
- 기관/Lab 관리와 기업 연구소/B2B
- 결제·계약·산학협력단 행정
- 연구성과·IP·문서 워크플로 고도화

필요해 보인다는 이유만으로 범위에 추가하지 않습니다. 팀 합의 후 이 문서와 의사결정 로그를 먼저 수정합니다.

## 4. 반드시 분리할 세 상태

| 상태 | 답하는 질문 | 예시 |
|---|---|---|
| Availability | 전문가는 새 협업을 받을 수 있는가? | 바로 가능, 날짜 협의, 현재 어려움 |
| Relationship | 나와 대상 사이의 요청 관계는? | 요청 보냄, 검토 중, 수락, 거절 |
| Project Status | 확정 프로젝트가 어디까지 왔는가? | 예정, 진행 중, 종료 대기, 완료 |

전문가에게 진행 중인 프로젝트가 있다는 사실만으로 `현재 어려움`으로 판단하지 않습니다.

## 5. 완료 기준(Definition of Done)

MVP 핵심 흐름은 다음 조건을 모두 만족할 때 완료로 봅니다.

- 연구자와 AI 전문가가 각자 필요한 프로필을 만들 수 있다.
- 두 매칭 경로가 이름과 상태를 섞지 않고 동작한다.
- 최종 선택된 사용자만 프로젝트 멤버 권한을 얻는다.
- 권한 없는 사용자가 비공개 정보와 개인 연락처에 접근할 수 없다.
- 프로젝트 멤버가 마일스톤을 진행하고 종료할 수 있다.
- 종료된 프로젝트에 대해서만 양방향 평가를 남길 수 있다.
- 주요 정상·권한 오류·빈 상태 흐름을 테스트했다.
- 실제로 검증한 내용과 아직 검증하지 못한 내용을 PR에 기록했다.

## 6. 현재 확인이 필요한 가설

- 공개 모집과 직접 요청 중 어느 경로가 더 빠르게 프로젝트로 전환되는가?
- 연구자는 Data Readiness·보안 항목을 어느 정도까지 입력할 수 있는가?
- 전문가는 어떤 정보가 있어야 프로젝트 참여 여부를 판단하는가?
- 팀은 외부 도구 대신 플랫폼 안에 마일스톤을 기록할 의사가 있는가?
