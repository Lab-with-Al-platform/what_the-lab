## 무엇을 변경했나요?

인사이트 담당자가 웹에서 수집후보·게시글을 조회하고, 전체 원고를 편집·검수할 수 있는 관리자 작업공간을 추가했습니다. 기존 공개본과 비공개 수정 판본을 분리해 수정 중 공개본이 유지되도록 했습니다. 수집 메모와 게시용 원고를 구분하고, 기존 글 31개 보존 이관 및 새 후보 6개의 설명 보강 도구를 추가했습니다. 출처 11곳의 협업사례/AI 트렌드 용도와 후보 부족 시 제한적 기간 확장 정책을 팀 공통 설정으로 저장합니다. **자동 수집·예약 worker·무인 게시·일반 공개 화면의 DB 전환은 구현 완료 범위가 아닙니다.**

### 주요 변경

- 계정 메뉴에 서버 권한 확인 후 **인사이트 관리자** 진입점 제공. 일반 로그인·회원/프로젝트 관리자 기능은 확장하지 않음.
- 전체 목록 / 수집후보 / 게시글 / 자동수집 설정 사이드바, 검색·유형·상태·게시본 기반 분야/키워드 필터.
- 제목·상태·유형·연구 분야·키워드·등록/수집일의 6열 목록, 6개씩 표시, 최대 5개 페이지 번호와 끝 화살표 비활성.
- 편집 모달: 전체 본문·출처/근거·승인/게시·판본 이력과 실제 `ArticleView`를 재사용한 본문 전용 웹(1440px)/모바일(390px) 미리보기.
- 후보 일괄 입력은 기본 미리보기이며 최대 50개. DOI/URL/유형 중복, 출처 충돌, 기존 편집·승인·공개본 보존과 트랜잭션 취소 검사.
- 수집 메모/게시용 원고 분리, 문단·용어 추가, 편집자 노트 유형 보존, 승인 전 독자 검수 6항목. 저장 시 승인 무효화, 미승인/근거 부족/트렌드 전용 검증 미연결 시 승인·게시 차단.
- 기존 공개 글을 읽기 전용 보존본으로 이관하고, 정식 수정 초안의 재승인·명시적 게시 때만 공개 API 스냅샷 교체.
- 출처 11곳의 복수 용도(`case`, `trend`), 구버전 설정 호환, 설정 버전 충돌 처리.
- 최근 30일 우선 탐색. 협업사례 30/60/90/180/365일, 최신 소식 30/60/90일, 기술 해설 30/90/365일의 예정 구간·상한 설정. 확장 기준 수와 최대 저장 수 분리, 조회량·시간 예산 저장.
- 편집·기간 정책 기준서, 개발 DB 적용 도구, 가상 관리자 테스트와 반응형 QA 기록.

## 리뷰어가 특히 봐야 할 점

1. **대상은 develop입니다.** 자동 병합·배포하지 않습니다. 별도 보안 PR #18은 여전히 별도 검토 대상입니다.
2. **설정 저장 ≠ 실제 수집.** 구간 계산과 정책 UI만 있습니다. 출처별 API/RSS/HTML 연결·이용 조건·호출 예산 집행·발표일 경계·최신 소식/해설 판정·예약 worker는 후속 작업입니다.
3. **공개 API 반영 ≠ 일반 사이트 반영.** 일반 사례/트렌드는 아직 정적 원고를 사용합니다. 관리자의 수정이 일반 페이지로 자동 노출되지 않습니다.
4. **사례와 트렌드의 검증을 섞지 않습니다.** 트렌드는 수집·편집·검토 대기까지만, 전용 검증 연결 전 승인/게시 차단입니다.
5. 이관은 새 논문 검증/승인 기록이 아닙니다. 기존 31개 중 가상 설계 시나리오 2개의 표시를 그대로 보존합니다. 신규 6개도 주장 검토는 `needs_review`이며 실제 연구 재현을 수행하지 않았습니다.
6. 삽화는 본문 검토 후 최종 승인 전에 준비하는 원칙만 반영했습니다. 신규 삽화를 생성하거나 권리 검수를 자동 완료하지 않았습니다.
7. 미저장 입력·설정 버전 충돌·승인 판본 일치·공개본 보존·중복 게시 방지를 우선 검토해 주세요.
