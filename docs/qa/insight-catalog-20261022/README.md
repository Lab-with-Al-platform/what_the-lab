## 2. 데이터 보존과 승인 경계

`frontend/scripts/export-insights.cjs`가 `INSIGHTS`의 **최종 보강 결과**를 내보냅니다. 초기 seed만 읽지 않으며 본문·용어·편집자 노트·표지 경로·이미지 설명·관련 글 등 모든 필드를 포함합니다.

`backend/app/insights/catalog_import.py`는 전체 원고를 revision 및 publication JSON에 보존합니다. 정렬한 JSON의 SHA-256을 비교해 전 필드 보존을 확인합니다. 기존 원고는 `origin=legacy_static`, 이력은 `legacy_imported`이며 `approved_by`, `approved_revision`, `approved_at`은 NULL입니다. 과거에 없던 관리자 승인을 만들어 내지 않습니다.

논문 하나를 다룬 여러 글도 보존하기 위해 기존 원고 Source는 논문이 아니라 `urn:labbridge:legacy-article:<slug>`라는 **보존 원고 식별자**입니다. 원래 논문의 URL·DOI는 전체 article JSON 안에 그대로 있습니다. 이 URN을 외부 논문 주소로 사용하지 않습니다.

이미지는 바이너리를 DB/Storage에 올린 것이 아니라 기존 `frontend/public` 파일 경로를 보존했습니다. 이미지 파일 업로드·재생성은 하지 않았습니다.

새 6개는 bibliography_checked=false, claims 모두 needs_review, 점수·운영 키워드 없음, no_image, 승인 없음, publication 없음입니다. 제목만 모은 것이 아니라 8개 본문 메모·근거 위치·출처 URL·DOI·용어 풀이를 작성했습니다. 수집이 관리자 원문 대조나 게시 승인 완료를 뜻하지 않습니다.

## 4. 관리자 화면과 현재 한계

확인 주소: `http://localhost:3000/admin/insights` — 실제 관리자 계정 로그인 필요.

- **수집 후보**: 미게시 후보만 조회. 사례/트렌드, 상태, 제목·DOI 검색, 페이지 이동.
- **게시 중인 글**: DB의 게시 보존본만 조회. 유형·제목 검색·페이지 이동. 선택하면 전체 본문, 편집자 노트, 용어 풀이와 현재 공개 페이지/원 출처 링크 표시.
- 목록은 요약 10개씩, 선택한 글만 전체 원고를 받아 목록 전송량을 줄입니다.
- 기존 글 보존본은 읽기 전용입니다. 새 후보 API에 이관 전용 우회 승인을 노출하지 않습니다.
- 트렌드는 별도 유형·쉬운 설명 필드명·용어 편집을 지원합니다. **전용 게시 검증 정책 연결 전까지 서버에서 승인·게시 차단**. 사례의 12점 평가를 해설에 억지로 적용하지 않습니다.
- **공개 사례·트렌드 페이지는 아직 코드의 원고를 읽습니다.** 관리자 목록은 Supabase입니다. 공개 페이지의 DB 전환과 게시 후 정정/원고 재동기화는 후속 작업입니다. 저장했다고 이 연동까지 끝난 것은 아닙니다.
- 신규 자료의 키워드 연결·표지 선정·원문 대조·편집 검토·실제 승인과 게시도 후속입니다.

## 5. 이관 실행과 재실행

`backend`에서 `.venv/Scripts/python.exe -m app.insight_catalog_setup`는 건수만 조회합니다.

쓰기 전 `--rehearse --confirm-project-ref <개발 프로젝트 번호> --node <Node 경로>`로 이관·검증 후 rollback합니다. 사용자가 지정한 개발 DB를 확인한 경우에만 `--apply`로 확정합니다. 연결 문자열·비밀번호를 명령이나 문서에 적지 않습니다.

실제 순서: 0건 확인 → 전체 이관 연습 후 rollback → 여전히 0건 확인 → 실제 이관 → 재실행 연습. 재실행 결과 기존 원고 31개·후보 6개 보존, 신규 생성 0건, 내용·판본·이력 변경 0건을 확인했습니다.

변경 전 자료 백업은 Git 제외 경로 `tmp/db-checkpoints/insight-catalog-*.json`에 있습니다. 이관 한 묶음을 한 트랜잭션으로 처리하고 기존 행 대조가 실패하면 모두 취소합니다. 슬러그는 같지만 내용 해시가 다른 기존 글을 자동 덮어쓰지 않습니다. 삭제나 DB 구조 변경은 하지 않았습니다.
