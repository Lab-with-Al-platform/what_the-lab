# 인사이트 후보 일괄 입력 — 자동화 후속 기반

## 1. 이번 단계와 다음 단계

사용자가 자동 게시 개발 재개를 요청하여, 기존 초안·검토·승인·게시 API에
관리자 전용 후보 일괄 입력을 추가했습니다. 관리자가 준비한 JSON 후보 묶음을
먼저 점검하고 명시적으로 요청한 경우에만 새 비공개 초안으로 저장하는 도구입니다.
논문을 찾거나 내용을 검증하는 수집기·AI 에이전트는 아직 아닙니다.

기준 브랜치: 최신 조회한 `origin/develop`의 `4be1f1c`에서 분기한
`feature/insight-candidate-import`. 별도 보안 PR #18과 섞지 않았습니다.
새 테이블·마이그레이션·의존성·프론트 화면은 추가하지 않았습니다.

전체 Phase 2 완료는 아닙니다. 연구 21건·실용 17건의 기준 자료 변환,
기존 CASE 코드 추적, 실용 사례 코드 합의, PDF의 점수/출처 보존,
원문 재검증은 후속 작업입니다. 실제 자료를 임의로 가상 초안으로 대체하지 않았습니다.

## 2. API와 저장 규칙

`POST /api/v1/admin/insights/candidates/import`

기존 인사이트 기능 플래그·관리자 검사·Origin 검사를 모두 재사용합니다.
로그인했다고 누구나 호출할 수 있는 API가 아닙니다.

| 입력 | 의미 |
|---|---|
| `drafts` | 기존 `Draft` 구조의 목록. 1~50개 |
| `dry_run` | 기본 `true`. 저장할 때만 실제 JSON boolean `false`를 명시 |

미리 보기도 현재 DB와 중복을 대조하므로 **서버 DB 연결은 필요**합니다.
‘저장하지 않음’과 ‘DB에 전혀 연결하지 않음’은 다릅니다.
단위 테스트는 별도의 임시 SQLite DB만 사용합니다.

응답의 `items[].index`와 `duplicate_of`는 입력 목록의 **0부터 시작하는 위치**입니다.

| action | 의미 |
|---|---|
| `would_create` | 미리 보기에서 새로 저장될 후보 |
| `created` | 명시적 저장 요청으로 생성한 비공개 초안 |
| `existing_preserved` | 동일 출처의 기존 후보를 유지. 입력 내용으로 덮어쓰지 않음 |
| `duplicate_in_batch` | 같은 묶음 앞부분의 동일 출처. 앞 후보에 연결하고 새로 만들지 않음 |

새 후보는 `draft`이며 **근거 재검토가 필요한 상태**입니다.
공개 API에는 들어가지 않습니다. 검토 요청·근거 보완·사람의 승인·게시 명령은
기존 절차를 따로 거쳐야 합니다.

### 입력 자료의 검증 표시를 그대로 믿지 않는 이유

이전 파일에 ‘검증 완료’라고 적혀 있어도 현재 원문과 권리까지 검토했다는 뜻은 아닙니다.
새 후보에는 다음 보수적 초기값을 적용합니다. 기존 편집본에는 적용하지 않습니다.

- `source.bibliography_checked=false`, `source.access_level=unknown`
- 모든 `claims[].verification=needs_review`
- `scores=[]`, `keyword_ids=[]`, `image_policy=no_image`

주장 본문·출처 링크·근거 위치는 검토 재료로 남기되 확인 완료로 선언하지 않습니다.
점수·기술 ID·이미지 권리는 관리자가 새 revision에서 확인해 입력해야 합니다.
수집기를 나중에 연결하더라도 이 API가 승인을 대신하지 않습니다.

## 3. 중복·실패·편집 보호

- DOI의 접두 URL·대소문자는 기존 정규화 함수를 재사용합니다. DOI가 없으면 URL을 사용합니다.
- 동일 DOI의 다른 출처 URL은 기존 후보를 보존합니다. 기존 대표 링크를 교체하지 않습니다.
- DOI와 URL이 서로 다른 기존 출처를 가리키거나 같은 URL의 DOI가 다르면 409로 중단합니다.
- 같은 제목이라는 이유만으로 다른 DOI/URL을 합치지 않습니다. 프리프린트와 정식판을 제목 유사도로 자동 병합하지 않습니다.
- 다른 출처가 같은 글 주소(`slug`)를 쓰려 하면 기존 후보의 현재 원고와 공개본을 확인해 중단합니다. 검사와 저장 사이의 모든 동시 slug 경합을 DB 제약으로 보장한 단계는 아닙니다.
- 묶음을 먼저 검사하고 나서 저장합니다. 중간 저장에 실패하면 요청 트랜잭션 전체를 취소합니다. 동시 DOI 입력의 DB 제약 충돌도 기존 409 처리로 취소하며, 최신 상태로 다시 미리 봅니다.
- 기존 수동 원고·검토 대기·승인·공개 스냅샷과 감사 기록은 재입력으로 바뀌지 않습니다.

핵심 코드는 `app/insights/importing.py`의
`plan_import()`(조회·검사) → `unverified_draft()`(검토 표시 초기화) →
`service.create_candidate()`(기존 저장 규칙) 순서입니다.
자동 승인·게시 함수는 호출하지 않습니다.

## 4. 검증 결과

2026-10-22 이 브랜치에서 수행했습니다.

- 새 일괄 입력 검사 **19개 통과**.
- 백엔드 전체 **82 passed, 1 skipped**. 전용 PostgreSQL 동시성 검사는 별도 URL/실행 설정이 없어 생략했습니다.
- 수정 Python 파일 Ruff 검사·형식 검사 통과.
- 기본 미리 보기의 저장 0, 같은 자료 3회 입력 후 후보 1개, 제목 유사 자료 분리 확인.
- 검증·키워드·권리 표시 초기화, 근거 부족 승인 차단, 기존 승인·공개본 보존 확인.
- DOI/URL 충돌·slug 충돌·두 번째 쓰기 실패 시 묶음 취소 확인.
- 로그인/관리자/Origin/기능 플래그·50개 상한·엄격한 boolean 검사 확인.

모든 신규 검사는 가상 계정·가상 논문·임시 DB에서 수행했습니다.
실제 Supabase 후보 반입, 실제 PostgreSQL 다중 작업자 import 경합,
원문 조회, 실제 Discord 로그인, 관리자 UI/공개 화면 E2E는 미검증입니다.
기존 Starlette/httpx 테스트 도구 경고 1개는 별도 개선 대상으로 남았습니다.

## 5. 로컬에서 확인하는 방법

`backend` 폴더에서 DB 없이 안전하게 단위 검사할 수 있습니다.

```powershell
uv run pytest -q tests/test_insight_import.py
uv run pytest -q
uv run ruff check app/insights/importing.py app/insights/schemas.py app/routers/insights.py tests/test_insight_import.py
```

기존 서버 실행 방식은 같습니다.

```powershell
uv run uvicorn app.main:app --reload --port 8000
```

`http://localhost:8000/docs`에서 새 `POST /api/v1/admin/insights/candidates/import`의
입력 구조를 확인할 수 있습니다. 호출은 활성화된 인사이트 기능과 같은 브라우저의
관리자 로그인·허용된 Origin이 필요합니다. 명령행 도구에 쿠키·토큰을 복사해 공유하지 마세요.
실제 DB에 저장하는 `dry_run=false`는 이번에 실행하지 않았습니다.
가상 테스트 자료를 공용 DB에 넣지 않습니다.

일반 `/cases`, `/trends` 화면의 변화는 없습니다. 후보 입력 백엔드 단계이기 때문입니다.

## 6. 남은 순서와 종료 조건

이번 묶음은 일괄 입력 API·오프라인 검사가 끝난 상태입니다. 자동 게시 전체 완료가 아닙니다.

다음은 기준 자료를 실제 출처·기존 코드에 맞춰 정리하고 대표 1건의 근거를 검토하는 단계입니다.
전체 fixture는 추적 코드·출처·인용·점수 보존 계약을 확인한 뒤 별도로 구성합니다.
그다음 외부 API의 최신 인증·요금·이용 조건을 확인하고 수집기를 연결합니다.
AI 초안, Keyword Master 연결, 관리자 화면 연계, 승인 글 편성·예약 worker는 각 검증 후 진행합니다.
대량 수집·유료 호출·운영 예약 등록·무인 게시를 임의로 켜지 않습니다.
