# 관리자 연구 진행 상태 — 2026-10-26

## 결과

- 연구 목록의 작성 상태 다음에 **진행 상태** 열을 추가했습니다.
- 작성 상태와 독립적인 진행 상태 필터를 추가했습니다. 검색·기간·분야 조건과 조합하고 초기화할 수 있습니다.
- 연구 상세에도 같은 배지와 상태 설명을 표시합니다.
- 데모에는 모집 중 / 모집 종료·미매칭 / 진행 예정 / 진행 중 / 완료 예시가 있습니다.
- 실제 등록 연구는 연동 전, 임시저장 연구는 해당 없음입니다. 구형 API 응답도 같은 원칙으로 처리합니다.
- 모집·협업 상태를 작성 상태 필드에 덮어쓰지 않습니다. DB 스키마·실제 업무 상태·권한을 바꾸지 않았습니다.
- 상태 용어, 시작일과 모집 기한의 관계, 추가 검토할 상태는 [기획 보완](../../planning/ADMIN_RESEARCH_PROGRESS_2026-10-26.md)에 기록했습니다.

## 코드 흐름과 변경 이유

1. 서버의 `_research_progress()`는 실제 상태 원천이 없으므로 등록 연구에 `not_linked`를 반환합니다. 임시저장은 별도 처리합니다.
2. API의 `progress_status`는 허용된 코드만 받고 서버에서 필터링합니다. 현재 원천이 없는 모집/진행 상태 필터는 빈 결과를 반환합니다.
3. 프론트의 `researchProgress()`는 코드와 배지 문구를 연결합니다. 진행 정보가 없는 구형 응답과 알 수 없는 코드도 안전하게 표시합니다.
4. 목록·상세는 같은 `ProgressBadge`를 사용해 문구가 달라지는 문제를 막습니다.
5. `admin-demo.ts`는 가상 진행 상태만 제공합니다. 서버 전송·DB 저장 코드는 없습니다.

‘등록’을 ‘모집 중’으로 바꾸는 방식보다 상태를 분리하면 미확정 정보가 실제 업무 사실처럼 보이는 오류를 막을 수 있습니다.

## 검증

- TypeScript 타입 검사 통과.
- 변경 프론트 파일 ESLint 통과, 서버 변경 파일 Ruff 통과.
- 프론트 관리자 테스트 22/22 통과(대시보드 7개 + 기존 인사이트 관리자 15개).
- 서버 운영 조회 테스트 10/10 통과. 응답/상세 일치, 필터 조합, 잘못된 코드 422, 기존 권한 경계 포함.
- 격리 복사본에서 Next.js 프로덕션 빌드·61개 정적 페이지 생성 통과.
- 빌드의 기존 경고 3개(가입 완료 화면 미사용 변수, SiteHeader img 권고 2개)는 이번 범위 밖으로 유지.
- 프로덕션 브라우저에서 1440/768/390px 캡처, 진행 상태 필터·작성 상태 교차 검색·빈 결과·초기화·상세 이동 확인.
- 실데이터 모드와 구형 API 응답에서 모집/진행 상태를 추측하지 않음을 확인.
- API는 모두 가상 응답이며 테스트 쓰기 0건, 브라우저 실행 오류 0건. [검증 결과](verification.json)

처음의 제한 환경 실행은 pytest 임시 경로 권한과 빌드 디렉터리 권한 문제로 중단되었습니다.
허용된 임시 작업 경로와 격리 실행 환경에서 재실행해 위 결과를 확인했습니다. 테스트 기대값은 바꾸지 않았습니다.
브라우저의 select 탐색은 필드 name 속성으로 지정했습니다.

실제 로그인·원격 DB·모집/협업 모듈 연동·자동 마감 시각·업무 상태 전환·실기기·화면낭독기는 미검증입니다.
원본 `frontend/.next`와 `.env`는 빌드에 사용하지 않았습니다. 커밋·push·배포는 하지 않았습니다.

학습 힌트: 모집 기한이 끝났더라도 이미 매칭된 프로젝트가 ‘미매칭’으로 바뀌면 안 되는 이유를 생각해 보세요.
