# 인사이트 관리자 작업공간 개편

> 후속 화면 변경: 제목 6행 목록과 웹/모바일 본문 전용 미리보기는 [최신 검증 기록](../insight-compact-preview-20261022/README.md)을 참고하세요. 아래는 최초 개편의 검증 기록입니다.

2026-10-22 사용자 후속 합의: 전체 목록 기본 화면, 확장 가능한 사이드바, 통합 필터 목록, 편집·미리보기 모달, 자동수집 설정 저장, 공개본을 유지하는 수정 초안.

## 구현 범위와 사용 순서

주소: `http://localhost:3000/admin/insights` — 실제 관리자 계정 로그인 필요.

1. **전체 목록**에서 수집후보·게시글을 등록/수집일 순으로 확인합니다. 원 게시 표기일은 별도입니다. 기존 31개는 이관 시각이 등록일이며 원 논문의 발표일과 혼동하지 않습니다.
2. **수집후보 / 게시글** 메뉴는 같은 목록의 조회 범위를 바꿉니다. 게시 중인 글에 수정 초안이 있으면 ‘게시 중 · 수정 초안’으로 표시하며 수집후보 메뉴에도 나타납니다. 전체 목록에서는 같은 원고를 중복 행으로 만들지 않습니다.
3. 검색·분야·키워드·사례/트렌드·검토 상태·후보/게시글 필터와 최신/오래된 순 정렬을 조합합니다. 분류 키워드는 기존 글 태그·수집 메모·용어 라벨이며 운영 승인 CAP ID가 아닙니다. Keyword Master를 자동 승인하지 않습니다.
4. 원고 행을 선택하면 모달을 엽니다. PC는 좌측 편집/우측 실제 기사 구성 미리보기, 모바일·태블릿은 편집/미리보기 탭입니다. 닫은 뒤 목록의 검색·필터를 유지합니다.
5. 미게시 후보는 판본 저장·근거 검토·검토 요청·승인·수동 게시의 기존 절차를 재사용합니다. **트렌드의 전용 게시 검증은 아직 연결되지 않아 승인·게시가 차단**됩니다.
6. 공개 글은 처음에는 읽기 전용입니다. 이유를 적고 **수정 초안 만들기**를 누르면 전체 본문·편집자 노트·용어·기존 메타데이터를 보존한 별도 판본을 만듭니다. 수정 중 공개본은 그대로입니다. 미리보기에서 편집 중 초안·저장 판본·현재 공개본을 선택할 수 있습니다.
7. **자동수집 설정**은 간격, 한국 시간 기준 시각, 최근 자료 기간, 후보 수 상한, 검색어와 출처 이름/HTTPS 주소/대상 여부를 DB에 저장합니다. 원문 다운로드 권리·출처 연결 검증까지 완료된 것은 아닙니다. API 키·암호를 입력하는 기능은 아닙니다.

## 반드시 구분할 미완료 경계

- **설정 저장 ≠ 수집 실행.** worker·예약 실행·‘지금 수집하기’ API/버튼은 구현하지 않았습니다. 다음 수집 시각·최근 실행 성공 같은 가짜 운영 상태도 표시하지 않습니다.
- **공개 API 반영 ≠ 일반 사이트 반영.** 일반 사례·트렌드 페이지는 아직 코드의 정적 원고입니다. 미리보기는 실제 ArticleView 구성요소를 사용하지만 초안을 사이트에 게시하는 동작은 아닙니다.
- 수정 초안의 승인만으로도 공개 스냅샷은 바뀌지 않습니다. 재승인 뒤 **명시적 게시**를 실행해야 공개 API 스냅샷만 바뀝니다. 기존 공개 URL/게시물 ID/원 게시 시각은 유지하고 이전 스냅샷은 불변 판본에 남깁니다.
- 이번 작업에서 실제 개발 DB의 글을 수정·승인·교체하지 않았습니다. 실제 Discord 로그인 성공을 자동으로 검증하지도 않았습니다. 테스트의 가상 계정을 실제 서버 인증 우회로 추가하지 않았습니다.
- 글별 이미지 업로드·재생성·출처 원문 수집·유료 API·Git commit/push·PR·운영 배포도 실행하지 않았습니다.

## 핵심 코드 흐름 — 학습용

- `insight_workspace.workspace()`: 현재 판본과 공개본을 연결하고 목록용 제목·분류 JSON 조각만 읽습니다. 소규모 관리자 목록의 분류·필터·페이지 구성을 처리합니다. 본문 전체를 목록마다 전송하지 않습니다. 대규모 운영의 SQL 분류 인덱스/정규화는 후속 최적화 대상입니다.
- `corrections.start_correction()`: 기존 공개 스냅샷을 건드리지 않고 새 비공개 판본을 만듭니다. 기존 승인·점수·근거 확인을 새 승인으로 복사하지 않습니다. 이미 작업 중이면 덮어쓰지 않고 기존 수정본을 엽니다.
- `corrections.save_correction()`: 전체 원고와 별도의 주장/근거 검토 자료를 저장하고 승인을 무효화합니다. 주소·유형·출처 식별자와 시나리오/이미지 권리 표시를 임의로 바꾸지 못하게 검사합니다.
- `service.publish_candidate()`: 버전·관리자 승인·근거·예약 시각을 다시 확인합니다. 수정본의 경우에만 같은 공개 스냅샷을 교체하고 중복 요청을 막습니다. 이전 공개 스냅샷은 판본 JSON의 `base_publication_snapshot`에 남습니다.
- `InsightEditorDialog`: 편집 상태를 임시로 보관하고 저장 동작을 분리합니다. 409 충돌이면 입력을 보존합니다. 승인/게시 응답이 유실되면 자동 재전송하지 않고 서버 상태를 다시 읽습니다.
- `InsightLivePreview`와 `/admin/insights/preview`: 현재 편집 내용을 같은 출처의 iframe으로 전달하고 실제 ArticleView를 재사용합니다. 부모 창/출처를 확인하고 내용이나 토큰을 URL에 넣지 않습니다. 미리보기 자체는 DB를 쓰지 않습니다.
- `CollectionSetting`: 팀 공통 설정을 저장하는 한 행입니다. `expected_version` 검사와 행 잠금으로 다른 관리자의 수정 덮어쓰기를 방지합니다. GET은 저장 동작이 아니며 최초에는 ‘아직 저장하지 않은 기본 제안값’입니다.

## DB 변경과 보존

- 개발 프로젝트: `labbridge-dev`, 명시적으로 일치 확인한 연결에만 적용.
- 기존 보안 migration `20261021_03_updated_at_search_path.py`는 별도 작업 브랜치 `feature/fix-function-search-path`에서 **내용 변경 없이** 가져와 후속 이력을 연결했습니다. 이미 DB에 적용된 03을 다시 적용하거나 이력을 임의로 stamp하지 않았습니다.
- 새 migration `20261022_04`: `insight_private.collection_settings` **표 하나만 추가**. RLS 활성화, PUBLIC/anon/authenticated/service_role 직접 접근 차단.
- `app.insight_workspace_setup`: 적용 연습 후 rollback → 실제 적용. 변경 전 5개 인사이트 표를 `tmp/db-checkpoints/workspace-schema-*.json`에 보관하고 모든 기존 행을 대조했습니다.
- 적용 뒤 기존 sources/candidates/revisions 각 **37**, review_events **43**, publications **31** 그대로입니다. 회원 테이블·기존 글·공개본·후보 상태를 바꾸지 않았습니다.
- 실제 PostgreSQL에서 기존 31개 전체 원고의 입력 구조, 통합 목록 37/수집후보 6/게시글 31과 설정 저장·재조회 연습을 확인한 뒤 설정 연습 데이터는 전부 rollback했습니다. **실제 설정 행은 0개**이며 관리자가 화면에서 저장하기 전에는 기본 제안값만 보입니다.
- 자동 downgrade는 설정을 삭제할 수 있어 차단했습니다. 기존 테이블 삭제·DB 데이터 정리는 하지 않았습니다.
