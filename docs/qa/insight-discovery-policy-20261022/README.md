# 후보 부족 시 제한적 기간 확장 — 설정·계획·UI

확인일: 2026-10-22. `feature/insight-candidate-import`의 현재 미커밋 작업본 기준입니다.
사용자 요청에 따라 기간 확장 정책과 관리자 설정 화면을 변경했습니다.
기존 미커밋 작업을 보존했으며 커밋·push·PR·배포·실제 수집·승인·게시를 하지 않았습니다.

## 반영한 정책

| 항목 | 저장값 |
|---|---|
| 우선 탐색 기간 | 최근 30일, 확장 사용 중에는 고정 |
| 협업사례 | 30 → 60 → 90 → 180 → 365일 |
| 트렌드 최신 소식 | 30 → 60 → 90일 |
| 트렌드 기술 해설 | 30 → 90 → 365일 |
| 회차당 최대 저장 수 | 기존 1개 유지 |
| 기간 확장 기준 후보 수 | 1개, 최대 저장 수 이하 |
| 출처 요청 수·시간 상한 | 초기 제안 30회·120초, 관리자 변경 가능 |
| 날짜·과거 연구 | 발표일 기준, 상한보다 오래된 대표 연구는 별도 발굴 |

기간은 달력상의 개월 수가 아니라 일수입니다. 기준 수는 새로 찾은 중복 제외 적합
후보를 뜻하며 기존 재고·게시 할당량·검증 완료 수와 다릅니다. 적합성의 최종 판단·
출처 검증·승인은 그대로 별도 단계입니다. 범위·요청량·시간 상한에 도달하면 부족한
채 종료하고, 오류·호출 제한을 후보 없음으로 오인하지 않는 운영 원칙을 기준서에 남겼습니다.

## 구현과 미구현의 경계

- 새 `discovery_policy` JSON에 활성 여부·기준 수·성격별 상한·예산·날짜 기준을 저장합니다. DB 스키마 변경은 없습니다.
- `collection_policy.py`는 예정 구간만 계산합니다. 예를 들어 (0,30), (30,60)의 두 범위를 계획해 최근 30일을 다시 조회하지 않도록 표현합니다. 실제 날짜 경계·API 페이지네이션을 실행하지 않습니다.
- UI에서 최대 저장 수를 줄이면 확장 기준 수도 그 이하로 조정합니다. 서버도 기준 수 초과·최신 소식 90일 초과·예산 범위 초과·잘못된 활성값을 거절합니다.
- 자동 확장을 끄면 기존 고정 기간 방식을 선택할 수 있습니다. 다시 켜면 우선 기간은 30일로 돌아갑니다.
- 구버전 설정 GET은 자동 확장을 켜거나 DB에 쓰지 않습니다. 이번 사용자가 승인한 적용 도구만 버전 확인·백업 후 새 정책을 저장합니다.
- 요청 수·시간 제한의 실제 집행, 원문 발표일 확보, 적합 후보 선별, 최신 소식/기술 해설 판정·분기, 과거 자료 발굴 실행은 수집기 연결 때 검증합니다. 현재는 설정 저장·계획 미리보기뿐이며 `execution_available=false`입니다.

## 실제 개발 DB 적용·보존

개발 `labbridge-dev`에서 적용 전 버전 2 / 우선 기간 30일 / 최대 저장 1개 /
출처 11곳 / 새 정책 없음 상태를 조회했습니다. 같은 버전일 때만 모의 적용·롤백 후
실제 저장했고, 별도 재조회로 버전 3과 새 정책 전체를 확인했습니다.
수집 간격·기준 시각·검색어·출처 이름/URL/용도/선택·최대 저장 수는 보존했습니다.
기존 출처·후보·판본·검토 이력·공개본의 전체 JSON도 적용 전후 일치합니다.
