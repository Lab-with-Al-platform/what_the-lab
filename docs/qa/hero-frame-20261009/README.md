# 상단 이미지 프레임 넘침 수정 QA

검증일: 2026-10-09. 홈·AI 연구 협업 사례·AI 트렌드에 적용했습니다.

## 해결한 문제

- 홈의 `HeroCollage`는 화면 폭과 본문 최대 폭의 차이를 음수 여백으로 계산하여 오른쪽 화면 끝까지 늘어나고 있었습니다. 2880px 화면에서 아래 카드 프레임보다 740px 오른쪽으로 나갔습니다.
- 사례·트렌드 추천 사진은 화면 전체 폭인 `section` 안에 절대 위치로 놓여 있어, 본문이 최대 폭에 도달해도 사진은 계속 넓어졌습니다.
- 세 페이지의 이미지와 그라데이션을 기존 `PageContainer` 안으로 옮겼습니다. 이제 본문과 동일한 최대 1400px 프레임을 사용합니다.
- 기존 사진·카드·제목·그라데이션·설명 카드 위치 값·필터·정렬·페이지네이션 데이터는 유지했습니다. 기존 Cursor 변경과 이전 QA 캡처도 보존했습니다.
- 사례의 작은 ‘연구자의 시선’은 유지하고, 트렌드에는 다시 추가하지 않았습니다. 새 기능이나 콘텐츠를 추가하지 않았습니다.

## 핵심 코드와 선택 이유

이미지를 ‘화면 전체 크기의 액자’가 아닌 ‘카드 목록과 같은 크기의 액자’ 안에 넣는 변경입니다. 새 최대 폭 숫자를 별도로 만들지 않아, 나중에 공통 프레임 폭을 바꾸면 이미지도 함께 바뀝니다.

1. `PageContainer`: 헤더·본문·카드가 사용하는 공통 폭을 재사용합니다.
2. `relative`: 내부의 절대 위치 이미지·그라데이션이 이 프레임을 기준으로 배치되게 합니다.
3. `overflow-hidden`: 이미지와 시각 효과가 프레임 경계 밖에 그려지지 않게 합니다. 페이지 전체의 가로 넘침을 숨기는 방식은 사용하지 않았습니다.
4. 홈 `min-w-0`: 그리드 안의 이미지 영역이 화면이 좁아지면 필요한 만큼 줄어들 수 있게 합니다.
5. 사례·트렌드 내부의 중복 `PageContainer`는 일반 `div`로 바꿔 좌우 여백이 두 번 들어가지 않도록 했습니다.

이전: 본문은 최대 폭, 이미지는 화면 폭 → 축소 시 정렬선이 달라짐.

변경: 본문과 이미지는 같은 프레임 → 넓은 화면에서도 같은 정렬선 유지.

- 위 12개 화면과 3840 × 1000의 세 페이지, 총 15개 조건에서 DOM의 좌우 경계를 측정했습니다. 이미지가 공통 프레임 안에 있고 페이지 가로 넘침이 없었습니다.
- 2880px 홈: 이미지 오른쪽과 카드 프레임 오른쪽의 차이가 740px → 0px로 줄었습니다(소수점 반올림).
- 2880/3840px에서 세 페이지의 프레임 폭은 모두 1400px입니다.
- 홈 이미지는 기존처럼 1024px 미만에서 숨겨집니다. 모바일에 새 이미지 영역을 추가하지 않았습니다.
- 사례의 H1과 추천 사진 영역은 분리된 상태를 유지했습니다. 사례 인용 섹션은 존재하고 트렌드 인용 섹션은 없습니다.
- 사례 생성형 AI 필터: 내부 URL `AM-04`, 결과 1개. 트렌드 LLM·에이전트 필터: 결과 3개. 기존 동작을 확인했습니다.

## 빌드와 검증 한계

- `npm run build` 성공: 타입 검사·ESLint 검사 및 41개 정적 페이지 생성 완료.
- 기존 `article-view.tsx`, `cover-art.tsx`의 `<img>` 최적화 권장 경고 2건은 남아 있습니다. 이번 수정 파일에서 새 경고는 없습니다.
- 재시작한 로컬 개발 서버에서 세 페이지의 정상 표시와 프레임 경계를 다시 확인했습니다. 검증 마지막 브라우저 오류 로그는 없었습니다.
- `git diff --check` 통과. 커밋·push·외부 배포는 하지 않았습니다.
- **실제 브라우저 줌 비율을 조작한 테스트는 아닙니다.** 줌 아웃하면 CSS 기준 가로 공간이 늘어나는 조건을 2880/3840px 뷰포트로 재현했습니다. 실제 Ctrl+- 비율별 화면, 다른 브라우저, 실물 모바일 기기는 미검증입니다.
- 스크린샷은 로컬 개발 화면이므로 개발 도구 표시가 포함될 수 있습니다.

직접 확인할 힌트: 브라우저에서 Ctrl+-로 축소했을 때, 이미지 오른쪽 끝과 아래 마지막 카드 오른쪽 끝이 같은 세로선에 놓이는지 보세요.
