## 저장·기존 설정 보호

- `CollectionSource.content_kinds`에 `case`·`trend` 배열을 저장합니다. 단일 용도·복수 용도·빈 배열을 지원하고 알 수 없는 값·중복 값은 서버에서 거절합니다.
- 기존 JSON 설정에 필드가 없을 때만 알려진 출처의 제안을 보완합니다. 사용자 출처는 추측하지 않고 미분류로 둡니다. 사용자가 저장한 빈 배열도 그대로 유지합니다.
- GET은 DB를 수정하거나 추천 출처를 재추가하지 않습니다. 따라서 관리자가 삭제한 출처가 재조회 때 복구되지 않습니다.
- 추천 추가 도구는 기존 순서·이름·URL·대상 선택·명시적 분류와 주기·검색어를 보존하며 URL 끝 `/` 차이로 중복 추가하지 않습니다. 20곳 상한을 넘으면 기존 출처를 지우지 않고 중단합니다.
- 기존 `expected_version` 충돌 검사, 관리자·Origin 검사, 외부 HTTPS URL·키/암호 미포함 검사와 실행기 미연결 상태를 유지합니다.

적용 전 저장된 수집 설정은 없었습니다(버전 0). `labbridge-dev`에서 백업과 모의 저장·
롤백 후 추천 출처 11곳·용도를 버전 1로 저장했고, 별도 조회로 저장 여부·버전·11곳을

백업: Git에서 제외된 `tmp/db-checkpoints/insight-sources-20261022T090108Z-928ff644.json`.
보존 검사: 기존 출처·후보·판본·검토 이력·공개본의 전체 JSON이 적용 전후 일치합니다.
실제 연구 원문 사이트에 접속하거나 자동 수집을 실행하지 않았습니다. 출처별 API/RSS/
HTML 연결·호출 제한·이용 조건·원문 이용 권한은 수집기 개발의 Phase 0 확인 대상입니다.

## 확인 위치·코드 흐름

`http://localhost:3000/admin/insights` → **자동수집 설정** → **원문·서지 출처 관리**.
각 출처의 ‘활용할 글’에서 용도를 선택한 뒤 **설정 저장**을 누릅니다.

화면 선택 → `content_kinds` 배열 → 서버 입력 검증 → 기존 설정 버전 확인 →
팀 공통 JSON 저장 순서입니다. 출처를 켜거나 분류를 바꾸어도 수집과 게시가 시작되지 않습니다.

학습 힌트: 하나의 출처가 두 용도에 해당할 수 있으므로 단일 문자열보다 배열이 맞습니다.
예를 들어 `["case", "trend"]`는 둘 다, `[]`는 아직 분류하지 않았다는 뜻입니다.
