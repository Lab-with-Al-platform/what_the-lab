## 구현과 이유

1. `CoverArt`의 일반 `img`를 `next/image`로 바꿨습니다. 원본 경로와 alt는 유지하고 `fill`로 기존 이미지 칸을 채웁니다. 크기·크롭·부모 배치는 바꾸지 않습니다.
2. `sizes`를 필수 값으로 받아 실제 표시 폭을 브라우저에 알립니다. 홈·목록·상세·관련 글의 서로 다른 칸 크기를 지정했고, 넓은 화면에서는 최대 콘텐츠 폭에 맞춰 상한을 뒀습니다. 작은 관련 글 표지는 `64px`입니다.
3. 대표 표지만 `priority`로 먼저 받고 나머지는 기본 지연 로딩을 사용합니다. 표지 선택과 실제 파일 보존 검사는 최적화 URL에서 원본 `url` 값을 꺼내 비교하도록 보완했습니다.
4. 홈페이지의 PC 전용 메인 이미지는 `getImageProps`의 최적화 `srcSet`과 `picture/source media`로 선택합니다. 모바일에서는 외부 요청이 없는 투명 픽셀을 사용합니다. 기존 숨김·데스크톱 구도는 그대로이며, CSS로만 숨긴 이미지의 불필요한 모바일 다운로드를 막았습니다.
5. 상세의 설명용 조직 사진도 `Image`로 전달합니다. 로그인 프로필의 외부 이미지와 원문 연구 도판을 일괄 변환하지 않았습니다.

원본 PNG/JPEG는 그대로 보관하며, 요청 시 Next 서버가 해당 화면에 필요한 크기·형식을 생성·캐시합니다. 기본 품질 75와 WebP 협상을 사용했고, 별도 AVIF·CDN·장기 캐시 정책은 추가하지 않았습니다. 이 구현은 [Next.js 15 이미지 컴포넌트 공식 문서](https://nextjs.org/docs/15/app/api-reference/components/image)의 `fill`, `sizes`, `priority`, 지연 로딩과 `getImageProps` 방식을 사용합니다.

## 실제 전후 측정

양쪽 모두 로컬 **프로덕션 빌드 + `next start`**, 동일 Chromium·로그아웃·화면 크기를 사용했습니다. 각 조건은 새 브라우저 컨텍스트여서 브라우저 캐시를 공유하지 않습니다. 서버의 최적화 캐시는 남을 수 있습니다.

측정치는 **이미지 HTTP 응답 본문 바이트 합계**입니다. HTML·JS·CSS·헤더, 실제 인터넷 회선 지연, 사용자 체감 로딩 시간 전체는 포함하지 않습니다. 초기값은 스크롤 전 관측이고 지연 로딩 범위는 브라우저가 결정합니다. 스크롤 후 누적값도 JSON에 별도로 남겼습니다. 비율만큼 전체 페이지가 빨라졌다는 뜻은 아닙니다.

## 재검증 방법

frontend 의존성을 설치한 환경에서:

```text
node --test frontend/tests/insight-reading.test.cjs
cd frontend
npx tsc --noEmit
npx eslint src/components/cover-art.tsx src/components/insight-card.tsx src/components/insight-browser.tsx src/components/article-view.tsx src/components/home-page.tsx
npm run build
npm run start -- --port 3000
```

빌드는 같은 `.next`를 사용하는 개발 서버와 동시에 실행하지 않습니다. 브라우저 검증 스크립트에는 Playwright·Chromium이 별도로 필요하며, 현재 생산 의존성에는 추가하지 않았습니다. `PLAYWRIGHT_MODULE`, `PLAYWRIGHT_CHROMIUM_EXECUTABLE`, `BASE_URL`로 실행 환경을 지정할 수 있습니다. 과거 측정값을 보존하려면 새 날짜의 QA 폴더에 스크립트를 복사해 기록합니다. `before`는 변경 전 기준 코드, `after`는 변경 후 코드에서 실행하며 동일 조건의 before.json이 필요합니다.

```text
node docs/qa/image-optimization-20261020/verify-images.cjs before
node docs/qa/image-optimization-20261020/verify-images.cjs after
node docs/qa/image-optimization-20261020/verify-variants.cjs
```

## 배포 전제와 미검증

- Next 이미지 최적화 API를 지원하는 서버/호스팅이 필요합니다. 정적 파일만 제공하는 배포라면 외부 로더 또는 사전 생성한 웹용 이미지 방식이 별도로 필요합니다. `unoptimized`를 켜서 원본 전달로 되돌리는 것을 해결로 보지 않습니다.
- 최초 요청의 변환 CPU·서버 캐시 저장 공간이 필요합니다. 배포 서비스의 변환 한도·요금·캐시·CDN 동작과 실제 느린 회선의 LCP/CLS는 아직 측정하지 않았습니다. 기본 이미지 캐시 응답 헤더는 변환 결과 JSON에 남겼습니다.
- 실기기 Safari·전 이미지의 전문가 판독 품질·스크린리더·로그인·관리자·DB 게시·배포는 이번 검증 대상이 아닙니다. 원문 연구 도판의 미세 정보를 압축본만으로 판독하도록 권하지 않습니다.
- 제출 PDF·실제 연구 자료·비밀정보는 포함하지 않으며 원본 이미지·이전 로컬 작업은 삭제하지 않습니다.

로컬 확인: [홈](http://localhost:3000/) · [사례](http://localhost:3000/cases) · [트렌드](http://localhost:3000/trends). 검증 서버는 `next start`로 실행했습니다.
