# 제목 중심 관리자 목록 · 웹/모바일 본문 미리보기

> 제목만 남긴 목록은 [6개 컬럼 표 후속안](../insight-table-20261022/README.md)으로 대체했습니다. 웹/모바일 본문 전용 미리보기는 유지합니다.

2026-10-22 사용자 요청: 목록은 제목만 간결하게, 편집 모달 오른쪽은 첨부 이미지의 중앙 본문만 표시하고 웹/모바일 전환을 제공.

## 변경과 동작

- 주소: `http://localhost:3000/admin/insights`. 실제 관리자 계정이 필요합니다.
- 전체 목록/수집후보/게시글은 제목 한 줄씩 6건을 표시합니다. 이전/다음으로 이동하고, 긴 제목은 모달에서 전체 내용을 확인합니다. 등록·수집 순서와 검색·유형·상태·분야·키워드 필터는 그대로입니다. 제목 툴팁에는 유형·상태·등록일을 보조 표시합니다.
- 상세 필터는 기본 접힘입니다. 기본 목록에서 불필요한 설명·표지·요약·키워드 행을 제거했습니다. 기본 글자 배율과 접힌 필터 기준 세 QA 화면에서 페이지 이동 버튼까지 스크롤 없이 보입니다. 필터 확장·브라우저 확대·짧은 화면까지 스크롤을 금지한 것은 아닙니다.
- 모달의 ‘웹 버전’/‘모바일 버전’은 판본 선택과 별도입니다. 기기를 바꿔도 입력·공개본·선택 판본은 변경하지 않습니다.
- 웹은 가상 화면 1440px에서 실제 본문 폭 토큰 720px만 잘라 표시합니다. 화면 반응형 기준은 1440px로 유지하므로 사진과 제목이 좌우로 배치됩니다. 모바일은 가상 화면 390px에서 이미지→제목 순으로 실제 재배치합니다.
- 오른쪽 패널 폭이 작아지면 `min(1, 표시 가능 폭 / 본문 폭)`으로 표시 배율만 줄입니다. iframe 내부가 보고한 전체 높이도 같은 배율로 줄여 마지막 문단까지 부모 영역에서 스크롤합니다. 목차 앵커도 부모 스크롤로 연결합니다.
- 같은 ArticleView의 `contentOnly` 선택사항을 사용합니다. 기본은 false이므로 일반 사이트는 경로·목차·오른쪽 정보·추천 콘텐츠를 유지합니다. 미리보기에서도 글 안의 용어·편집자 노트·본문·이미지 캡션은 보존합니다.
- 부모/iframe은 같은 출처와 창 식별을 확인해 메시지를 주고받습니다. 원고를 URL에 넣거나 프리뷰 자체가 저장 API를 호출하지 않습니다.

## 검증

- 새 브라우저 검사 13개 통과: `verification.json`. 실제 프론트에 격리 SQLite 테스트 API를 연결했습니다. 모든 API 요청이 GET인지 확인했으며 Supabase 쓰기는 없습니다.
- 기존 관리자 회귀검사 24개 통과: `regression/verification.json`. 초안·공개본 보존, 409 입력 유지, 중첩 확인창, 판본 전환, 권한, 승인 무효화, 응답 유실 재게시 방지를 가상 DB에서만 실행했습니다.
- 1440×900 / 768×1024 / 390×844에서 목록 6행과 페이지 버튼의 화면 내 위치, 가로 넘침 없음, 두 기기 모드 각각의 배치와 본문 끝 스크롤을 검사했습니다.
- 미저장 제목을 바꾼 뒤 모드를 왕복해도 입력과 미리보기가 유지됨을 확인했습니다. 일반 공개 글의 주변 정보가 남아 있는지도 별도 검사했습니다.
- TypeScript 검사와 변경 파일 ESLint(경고 0) 통과. 프론트 테스트는 본문 전용/일반 출력의 보존 테스트 2개를 추가해 총 30개 통과했습니다.
- 실행 중인 개발 서버의 빌드 폴더를 건드리지 않도록 별도 복사본에서 프로덕션 빌드 성공, 57개 경로 생성. 기존 회원가입 완료 화면의 미사용 변수 1건과 공통 헤더 img 경고 2건은 이번 범위 밖으로 남겼습니다.

## 보존 경계

실제 회원·인사이트·수집 설정 DB 변경, 실제 글 승인/게시, 수집 실행, 이미지 교체, Git commit/push/PR, 운영 배포를 하지 않았습니다. 일반 공개 사이트가 정적 원고를 사용하는 기존 경계도 유지합니다. 현재 기능을 확인하기 위해 기존 프론트 개발 서버를 재시작했습니다. 공용 백엔드는 중지하지 않았습니다.
