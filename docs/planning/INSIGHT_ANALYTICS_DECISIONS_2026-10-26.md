# 인사이트 조회수 구현 결정 — 2026-10-26

과거 운영 계획의 최상위 “이용 통계” 메뉴 대신, 조회수는 **인사이트 관리 안의 통계 탭**에만 둡니다. 좌측 관리자 메뉴는 기존 4개입니다. D-23의 운영형 인사이트 전체와 AI 블로그 자동화는 이번 작업으로 승격하지 않습니다.

## 콘텐츠를 어떻게 연결하는가

| 구분 | 식별자 | 조회수에 쓰는 방법 |
|---|---|---|
| 공개 사이트 | `frontend/src/lib/insights.ts`의 `kind` + `slug` | 화면이 보일 때 이 쌍만 서버로 보냄 |
| 관리자 게시본 | `insight_private.publications.id` | 조회수를 붙이는 변하지 않는 콘텐츠 ID |
| 후보·수정 판본 | `candidates.id`, revision number | 조회수 대상이 아님. 제목·slug가 바뀌어도 publication id는 유지 |

연결은 **유형과 slug가 정적 목록과 게시본에 둘 다 있을 때**만 합니다. 제목이 비슷해도 연결하지 않습니다. 게시본이 있는데 정적 목록에 없으면 `연결 확인 필요`이고 조회수 0으로 바꾸지 않습니다. 정적 글만 있고 게시본이 없으면 저장하지 않습니다. 공개 사이트를 DB 원고로 바꾸거나 정적 원고를 덮어쓰지 않습니다.

## PV

1회는 공개 글 상세가 브라우저에 보여 문서를 볼 수 있게 된 방문입니다. 목록 카드, hover, 서버 GET, 404, 미게시 후보, 관리자 편집·통계·미리보기는 제외합니다. 새로고침과 다시 방문은 새 조회입니다. 같은 방문의 Strict Mode 재실행은 sessionStorage의 같은 event id로 한 번만 셉니다. 하루 1회로 자르지 않습니다.

누적은 수집을 켠 뒤 받은 합입니다. 배포일 이전의 평생 조회수가 아닙니다. 측정 시작일은 처음 수락된 조회의 서버 시각입니다. 방문자 수·세션·체류·완독·가입 경로는 만들지 않습니다.

## 수집·보관

- 환경 변수 `INSIGHT_VIEWS_ENABLED` 기본값은 `false`입니다. 이번 작업에서 사용자 `.env`를 켜지 않습니다.
- 꺼져 있고 기록이 없으면 `not_collected`(화면 `—`). 꺼져 있어도 예전 기록이 있으면 `paused`로 과거 수를 유지합니다. 켜져 있고 사건이 없으면 실제 `0`입니다.
- 브라우저는 `insight_page_views`에 직접 쓰지 않습니다. `POST /api/v1/insights/views`만 호출하고, 응답에는 합계를 넣지 않습니다.
- 저장 최소 필드는 event id, 서버가 확인한 publication id, 서버 수신 시각입니다. Discord ID, 이메일, JWT, 쿠키 값, IP, 본문, 검색어, URL query는 분석 표에 넣지 않습니다. 요청 횟수 제한용 IP 해시는 메모리에만 있습니다.
- 일별 표 `insight_page_view_daily`의 합으로 기간·주·월 PV를 만듭니다. 이 합으로 고유 방문자를 계산할 수 있다고 보지 않습니다.
- 원본 행을 나중에 지우면 일별 합은 남고, 지운 원본으로 과거 사건을 다시 만들 수 없습니다. 자동 삭제는 아직 없습니다.
- 날짜 저장은 UTC, 관리자 경계는 Asia/Seoul, 시작 포함·끝 제외입니다. 오늘이 들어 있으면 집계 중이라고만 표시하고 증감률은 만들지 않습니다.
- 마이그레이션 파일은 `20261026_07`입니다. 이 작업 폴더에는 `20261025_06` 파일이 없어, 로컬 부모는 있는 마지막 개정 `20261022_05`입니다. 원격 DB는 이미 06까지 적용되어 있으므로 지금은 적용하지 않습니다. 06 파일이 같은 브랜치에 들어온 뒤 `down_revision`을 `20261025_06`으로 바꾸고 적용해야 사슬이 한 줄이 됩니다.

## 누가 보는가

통계 API는 기존 인사이트 관리자(`is_admin` 또는 인사이트 허용 목록)만 통과합니다. 운영 조회 권한만 있는 계정은 403입니다. 인사이트 허용 목록만으로 회원·연구 API가 열리지는 않습니다. 디자인 데모(`statsDemo=1`)는 그 권한 확인 뒤에만 보이고, 서버로 가상 글을 보내지 않습니다.

## 수집을 켜기 전에 남은 운영 결정

1. 원본 행을 얼마나 보관하고, 누가 삭제할 수 있는지.
2. 로컬 개발 서버의 조회를 공용 DB에 남길지, 개발 DB만 쓸지.
3. 누가 `INSIGHT_VIEWS_ENABLED`를 켤 수 있는지.
4. 정적 글과 게시본 slug가 어긋난 기존 글을 누가 연결할지. 코드는 자동으로 맞추지 않습니다.
