# Research × AI Collaboration Platform

## 화면 작업 전달용 --- MVP / MVP+ / Later

> 기준: 2026-10-01 통합 기획 + 시장조사 + 2차 회의 내용을 참고하되, 최신
> 논의인 **비대칭 양방향 매칭**을 우선한다.\
> 핵심 모델: **공개 모집(Open Recruitment) + 전문가 직접 요청(Direct
> Matching)**

------------------------------------------------------------------------

## 0. 한 줄 정의

**AI 기술이 필요한 연구 프로젝트와 연구 경험·기회를 찾는 AI 전문가가
서로 발견하고, 매칭된 뒤 실제 협업 종료까지 관리할 수 있도록 연결하는
플랫폼.**

### 제품 중심축

-   사람 디렉터리가 아니라 **Research Project ↔ AI Expert 매칭**
-   커뮤니티보다 **실제 협업 전환**
-   매칭 전에는 두 경로, 매칭 후에는 하나의 Collaboration Lifecycle
-   결제·계약·실시간 메신저는 MVP에서 직접 중개하지 않음
-   AI 기능은 콘텐츠 생성보다 **매칭/추천**을 우선

# 1. 핵심 사용자 Flow

## A. 공개 모집

``` text
연구자
  ↓
모집 프로젝트 등록
  ↓
AI 전문가가 프로젝트 탐색
  ↓
참여 신청
  ↓
연구자가 신청자 검토
  ↓
최종 선택
  ┐
  │
  ▼
실제 협업 프로젝트 생성
```

## B. 직접 요청

``` text
연구자
  ↓
AI 전문가 탐색
  ↓
협업 요청
  ↓
AI 전문가 검토 / 수락
  ↓
연구자가 최종 선택
  ┐
  │
  ▼
실제 협업 프로젝트 생성
```

## C. 매칭 이후 공통 Flow

``` text
최종 선택
  ↓
프로젝트 Draft / 조건 확인
  ↓
프로젝트 확정
  ↓
협업 진행
  ↓
일정 · 알림 · 외부 링크 관리
  ↓
프로젝트 종료
  ↓
양방향 평가
  ↓
협업 이력 축적
```

## W-02 요청/신청 관리

### 탭

-   받은 요청
-   보낸 요청
-   받은 신청
-   지원한 프로젝트

역할에 따라 불필요한 탭은 숨긴다.

### 거절

선택형 사유 + 기타 입력 - 일정이 맞지 않음 - 전문 분야가 다름 - 현재
참여 여력이 없음 - 기타

### 중요한 규칙

-   수락 ≠ 즉시 프로젝트 확정
-   여러 명이 수락/지원할 수 있음
-   최종 선택 이후 미선정 알림 필요
-   응답/선택 만료 규칙 필요

# 7. 화면 디자인 공통 원칙

1.  **목록 = 선택에 필요한 최소 정보**
2.  **상세 = 최종 판단에 필요한 정보**
3.  상태 Badge는 `Availability`, `나와의 관계`, `프로젝트 상태`를 섞지
    않는다.
4.  연구 특화 정보인 `Data Readiness`, `데이터 접근`, `NDA/IRB`,
    `투입량`을 일반 구인 플랫폼과의 차별 요소로 활용한다.
5.  연구자가 AI 용어를 잘 몰라도 등록할 수 있게 설명 문구와 선택형
    입력을 우선한다.
6.  AI 전문가는 "누군가 요청하기를 기다리는 사람"이 아니라 프로젝트를
    탐색하고 지원할 수 있어야 한다.
7.  실제 수치가 없는 초기 서비스에서는 허구의 성공률/만족도 통계를
    노출하지 않는다.
8.  모바일에서는 상단 메뉴가 사라지지 않도록 햄버거/드로어 내비게이션을
    제공한다.

# 8. 화면 작업 순서 추천

``` text
1. P-01 프로젝트 찾기
2. P-02 프로젝트 상세
3. E-01 AI 전문가 찾기
4. E-02 AI 전문가 상세
5. M-01 협업 요청
6. M-02 참여 신청
7. W-02 요청/신청 관리
8. W-03 프로젝트 확정
9. W-04 프로젝트 진행
10. W-01 대시보드
11. N-01 알림
12. R-01 평가
13. H-01 홈
```

> 이유: 홈부터 꾸미기보다 **핵심 매칭 Loop를 먼저 화면으로 연결**하면
> 누락된 상태와 액션을 빨리 발견할 수 있다.

# 9. MVP 성공 판단 지표

-   요청/신청 → 응답률
-   요청/신청 → 매칭률
-   매칭 → 실제 프로젝트 전환율
-   프로젝트 완료율
-   평균 응답 시간
-   재협업 의향/재협업률

회원 수나 게시글 수보다 **실제 협업 전환**을 우선해서 본다.

------------------------------------------------------------------------

# 10. 화면팀에 전달할 최종 핵심

> **공개 프로젝트 참여 신청과 전문가 직접 요청을 모두 유지한다.**\
> 두 경로는 매칭까지만 다르고, 이후에는
> `최종 선택 → 프로젝트 확정 → 진행 → 종료 → 평가`라는 하나의 Flow로
> 합친다.\
> MVP 화면은 이 Flow가 끊김 없이 동작하는 것을 최우선으로 설계한다.
