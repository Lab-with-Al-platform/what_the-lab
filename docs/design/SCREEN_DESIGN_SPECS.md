# LabBridge 화면별 UI 구현 명세 — 시안 충실도 기준

> 버전: 2026-10-09 검토본 / 대상: Next.js·React·Tailwind 개발자 및 GPT·Codex
> **최상위 시각 참조**: `design/AI 연구 플랫폼 랩브리지 랜딩페이지.png`, `design/LabBridge 암세포 분석 연구 페이지.png`.
> **보조 참조**: `design/labbridge-ui-v3/screens/`의 12개 이미지, `design/인사이트_시안/` 및 기존 WHAT THE LAB 자료는 **정보구조·콘텐츠 종류·동작 후보만** 참고한다. 최종 색·서체·그림자·카드 표현은 복제 금지.
> 수치와 색상은 화면을 보고 추정한 **구현 출발값(Proposed)**. Figma 원본 측정/팀 승인 전 확정값이 아니다.

## 1. 개발자가 반드시 지킬 우선순위

1. **기능 범위**: `docs/product/MVP_SCOPE.md`와 `docs/product/03_DECISION_LOG.md`를 확인한다. 시안에 보이는 기능이 모두 MVP는 아니다.
2. **시각적 기준**: 랜딩 이미지와 암세포 연구 상세 이미지만 P0. 나머지 시안은 P1 구조 참고.
3. **디자인 시스템**: `docs/design/STYLE_GUIDE.md`의 단일 토큰·컴포넌트 사용. 화면마다 색상·radius·그림자 재창조 금지.
4. **내용 신뢰성**: 이미지 안의 대학명, 성능 수치, DOI, 논문 제목은 검증 전 샘플이며 실제 사실처럼 노출 금지.
5. **검수**: 브라우저에서 실제 화면을 캡처하여 같은 폭의 기준 시안과 비교. 코드를 작성했다는 사실만으로 UI 완료 처리 금지.

| 랜딩 좌측 강한 2행 헤드라인, 우측 다층 연구 시각물 | `HeroCopy`와 `HeroVisual`을 별도 레이어로 배치. 텍스트가 이미지와 겹치지 않도록 반응형 재배치 | 일반 AI 스톡사진 하나로 대체하거나 텍스트를 이미지에 구워 넣음 |

| 상세 PC 왼쪽 목차, 중앙 논문형 본문, 오른쪽 연구정보·기술·관련 콘텐츠 | 3열 그리드, 본문 읽기 폭 확보, 좌측 sticky TOC, 우측 독립 패널 3개 | 본문을 화면 전체로 늘리거나 목차/우측 패널 생략 |
| 상세 중앙 상단에 메타·태그·도판·캡션이 정돈되어 있음 | H1/리드/메타/이미지/캡션을 구분; 원문과 연구 도판의 출처 표기 | 이미지 밑 캡션 없음, 출처 없이 DOI/성능 수치 생성 |
| `핵심 요약`은 라벤더 외곽 + 흰 4항목 패널 | 연구 문제 / AI 역할 / 주요 결과 / 적용 가능성, 동일 아이콘 스타일, PC 4열·모바일 1열 | 카드마다 다른 배경, 모바일 4열 강제, 내용 잘림 |
| 모바일 상세는 이미지 → 태그·제목 → 요약 → 목차 → 본문 | 이미지와 본문 정보의 순서를 모바일에서 명시적으로 재배치. 목차는 처음에는 일반 문서 흐름에 둠 | 모바일에서 PC 3열 축소 또는 처음부터 목차 화면 상단 고정 |

## 3. 디자인 토큰을 실제 CSS로 옮기는 규칙

- 기본 색(권장 시작값): brand `#5036F4`, ink `#101C3C`, secondary `#51607D`, page `#F8F9FD`, surface `#FFFFFF`, border `#E4E8F2`, summary `#F3F2FF`. **추정값**이므로 Figma 대조 전 `Proposed`.
- 시안의 전체 화면은 무채색 면적이 압도적이다. **보라는 링크/선택/CTA/요약 강조**에 집중. 트렌드·전문가 페이지 전체를 주황/청록으로 물들이지 않는다.
- 기본 폰트: 승인된 한글 산세리프(Pretendard 후보) + 시스템 폴백. 서체를 화면별로 바꾸지 않는다.
- 권장 단계: `12/13` 메타, `14/15` 카드 보조, `16/17` 본문, `18/20` 소제목, `24/28` 상세 H1 모바일, `28/34` 상세 H1 PC, `48/56` 랜딩 H1 PC. 본문 행간 `1.7~1.85`.
- 카드: radius 12px 내외, 1px 저대비 테두리, 약한 그림자 하나. 목록/상세/랜딩 카드의 종류는 다르더라도 공통 모서리/테두리 성격은 같다.
- 화면 최대폭: 1400px 내외(랜딩 1536px 기준 좌우 약 70px). 모바일 좌우 16~20px. **페이지별 좌우 정렬선 통일**.
- 반응형 후보: `<768px` 모바일, `768~1199px` 태블릿, `>=1200px` 넓은 화면. 실제 3열이 유지될 수 있는지 콘텐츠 기반으로 판단.
- Tailwind는 CSS 변수/테마 토큰을 참조한다. 임의의 `#...`, `shadow-xl`, `rounded-3xl`을 페이지 파일에 반복 추가하지 않는다.

## 4. 랜딩페이지 (`/`) — P0 시각 기준

### 4.1 1440~1536px PC

**헤더**
- 좌측 심볼과 `LabBridge` 워드마크, 탐색 `홈 / AI 연구 협업 사례 / AI 트렌드 / AI 전문가 찾기`, 우측 검색 아이콘과 회원가입·로그인.
- 흰색 단일 행. 활성 메뉴는 텍스트 색과 가는 하단 보라 선으로 구분. 메뉴 글씨를 H1처럼 키우지 않는다.
- 로고 원본 SVG/PNG 확보 전, 시안 전체 PNG에서 로고를 크롭해 쓰지 않는다.

**히어로**
- 상단 작은 대문자 `RESEARCH × AI × COLLABORATION`, 좌측 2행 제목 `연구의 질문이 / AI와 만나는 곳, LabBridge`와 짧은 설명, 보라 CTA.
- 제목은 문장 구조를 보존하고 `LabBridge`만 보라 강조. 이미지에서 추정한 PC H1 48~56px, line-height 1.14~1.2. 좁아지면 문구를 임의 축약하지 말고 font/열 폭을 조절.
- 우측 비주얼은 **단백질 구조, 의료 영상, 기후·환경 연구, 얇은 데이터 연결선, 투명 레이어와 작은 정보 라벨**이 함께 보여야 한다. 시안의 구도·농도·선명도가 핵심. 실제 사용 가능한 개별 이미지 자산/합성 배경 확보 필요.
- 이미지의 밝은 여백을 확보해 텍스트 가독성을 유지. 불필요한 패럴랙스·과한 glow 금지. 정적 대체 이미지도 허용하되 한 장의 흔한 연구실 사진으로 바꾸지 않음.

**세 개 탐색 카드**

> 2026-10-16 사용자 수정 합의: 아래 원형 화살표는 P0 원본 관찰 기록이다. 현재 구현은 원형 화살표를 제거하고 카드의 본문·이미지·여백을 목록 이동 링크로 사용한다. 기존 키워드 칩의 필터 링크는 유지한다. 마우스 호버 시 250ms 동안 4px 상승·배경 1.025배 확대·절제된 그림자 변화를 허용하며, 터치 중심 기기와 동작 줄이기 설정에서는 이동·확대를 사용하지 않는다. [검증 기록](../qa/home-cards-20261016/README.md) 참고.
- 카드 순서 고정: `AI 연구 협업 사례` / `AI 트렌드` / `AI 전문가 찾기`.
- 카드 내부 위쪽 영문 분류 라벨, 중간 큰 한글 제목과 2줄 설명, 오른쪽 둥근 화살표, 하단 분야/기술 칩.
- 가설: 3열 동일 폭, 카드 높이 약 210~230px, gap 16~20px, 내부 패딩 30~36px. 실제 시안과 비교해 조정.
- 사례는 논문·연구 관련 시각, 트렌드는 기술/곡면/연구 패턴, 전문가는 협업 연구 장면. 배경은 밝은 오버레이로 텍스트와 분리.
- 카드는 hover에서 작은 border/shadow 변화만 허용; 높이/위치가 튀거나 강한 색 반전 금지.

**최신 인사이트 + 연구자 인터뷰**
- 인사이트 3개는 동일한 이미지 높이/제목 행수/메타 위치, 별도 인터뷰 패널은 옅은 라벤더 바탕과 큰 인용문·출처·이동 링크.
- 인사이트 이미지 후보 16:9(실제 시안에서 가로형 썸네일); `object-fit: cover`로 주제를 유지하며 중심점은 카드별 `object-position`으로 조절.
- 제목은 2줄 내외, 요약 2~3줄, 날짜/북마크 아이콘은 하단. 단, **저장 기능은 현재 MVP+**이므로 비동작 아이콘을 완성 기능처럼 두지 않는다.
- 카드 하단 높이 정렬은 CSS Grid/Flex(`margin-top:auto`)로 해결. 고정 높이로 글자 자르지 않는다.

### 4.2 모바일
- 헤더: 로고 + 검색(기능 승인 시) + 메뉴. 모바일 메뉴는 실제 열고 닫히며 Esc/바깥 클릭/포커스 관리.
- 히어로: 헤드라인과 CTA가 먼저 읽히고 연구 비주얼은 아래로 이동하거나 배경 일부로 축소. 텍스트와 단백질/의료 이미지가 겹치지 않는다.
- 탐색 3카드는 1열, 카드 안 칩은 줄바꿈 허용. 화살표가 설명을 가리지 않음.
- 최신 인사이트 1열 → 인터뷰 패널. 인터뷰의 출처와 이동 링크 유지.

## 5. 연구 협업 사례 상세 (`/cases/[id]`) — P0 시각 기준

### 5.1 PC 3열과 콘텐츠 순서

```text
[공통 헤더 56~64px]
[브레드크럼]
┌─ TOC 150~180 ─┬──── 중앙 본문 620~720 ────┬─ 우측 230~270 ─┐
│ sticky         │ 태그·제목·리드·메타·도판     │ 연구 정보      │
│ 현재 섹션 표시  │ 핵심 요약 4항목             │ 관련 AI 기술   │
│                │ 본문·비교 이미지·흐름도      │ 관련 콘텐츠    │
└────────────────┴────────────────────────────┴────────────────┘
```

- PC 본문 H1은 이미지 기준 굵고 진한 네이비, 좌측 정렬. 보조 메타는 한 단계 낮은 명도. 상단 그림은 오른쪽 작은 영역에 들어가되 제목·리드 가독성을 침범하지 않는다.
- **모바일은 상단 이미지가 먼저** 나오고, 그 아래 태그·제목·설명·기관/날짜/읽는 시간·기술 태그가 이어진다. PC의 위치를 단순 축소하지 않는다.
- `핵심 요약`은 연보라 배경 컨테이너 안에 흰색 4항목, 작은 선형 아이콘. `연구 문제/AI 역할/주요 결과/적용 가능성` 고정 명칭.
- 본문 섹션은 `01.` 번호와 진한 제목, 설명 문단, 실제 연구 도판 4개 비교와 캡션, 데이터 수집→전처리→AI 모델 학습→결과 검증의 흐름도(해당 콘텐츠에 실제로 존재할 때만).
- 연구 정보의 필드는 분야/활용 기술/데이터 유형/기관/발표일/원문/DOI 중 실제로 검증된 것만. 오른쪽 정보 박스는 본문보다 강조하지 않음.
- 관련 기술은 짧은 쉬운 설명 + 기술 상세(존재 시). 관련 콘텐츠는 썸네일/제목/날짜. 기술로 전문가 찾기 CTA는 구현 범위와 실제 라우트를 확인.

### 5.2 목차 섹션과 앵커

| ID 예시 | 시안의 섹션 | UI 행동 |
|---|---|---|
| `research-problem` | 어떤 연구 문제였을까? | 본문 제목으로 이동 |
| `ai-method` | AI를 어떻게 활용했을까? | 본문 제목으로 이동 |
| `results` | 주요 결과 | 검증된 수치·조건과 함께 설명 |
| `applications` | 연구 의미와 활용 가능성 | 적용 가능성/한계 구분 |
| `limitations` | 고려할 점과 한계 | 제약 명시 |
| `references` | 관련 연구 및 자료 | 출처 링크 |

실제 섹션은 콘텐츠에 맞게 추가/변경 가능. **왼쪽 TOC와 모바일 TOC는 동일한 `sections[]` 데이터**를 사용한다. 존재하지 않는 앵커로 링크하지 않는다.

### 5.3 모바일 sticky 접이식 목차 — 상태 머신

| 상태 | 진입 조건 | 화면 | 사용자 행동/결과 |
|---|---|---|---|
| `inline-closed` | 첫 진입, 목차가 아직 상단에 도달하지 않음 | 본문 안 원래 자리의 `목차` 접힌 바 | 탭하면 `inline-open` |
| `inline-open` | 원래 자리에서 펼침 | 전체 목차 리스트 | 항목 선택→해당 섹션 이동·접힘 |
| `sticky-closed` | 스크롤하여 목차의 원래 위치가 **헤더 아래**에 도달 | 헤더 바로 아래 고정 바, 현재 섹션 제목 표시 | 탭하면 `sticky-open` |
| `sticky-open` | 고정된 목차를 펼침 | 현재 위치에 고정된 목록, 내부 스크롤 가능 | 항목 선택→이동·접힘 |
| `return-inline` | 위로 스크롤하여 원래 목차 위치 복귀 | sticky 해제, 문서 흐름에 자연스럽게 재배치 | 점프/깜빡임 없음 |

- **처음부터 `position:fixed`로 상단에 띄우지 않는다.** `position:sticky`를 문서 흐름에 사용하고, sticky 진입 감지는 필요하면 sentinel/IntersectionObserver로 수행.
- 접힌 바는 `목차` + 현재 섹션명 + chevron. 길면 한 줄 말줄임. 높이 약 44~52px 가설, 클릭/터치 영역 44px 이상.
- sticky top은 `var(--header-height)`; 앵커 목표 `scroll-margin-top: calc(var(--header-height) + var(--toc-collapsed-height) + 16px)`.
- 펼친 목록 높이는 `min(60vh, 360px)` 내외 가설; 목록 내부만 스크롤. `aria-expanded`, `aria-controls`, `aria-current="location"`, 키보드 Enter/Space/Esc.
- 스크롤 중 현재 읽는 H2를 활성 표시. `IntersectionObserver`를 사용할 때 rootMargin을 sticky 오프셋에 맞춰 조정하고, 섹션 사이 짧은 간격에서 활성 항목이 떨리지 않게 함.
- 펼침→섹션 이동 후 자동 접힘. `prefers-reduced-motion: reduce`면 강제 smooth scroll 금지.
- **본문의 끝 또는 기사 레이아웃 경계를 지나면 sticky가 종료**되어 관련 콘텐츠/푸터를 덮지 않음. iOS Safari 및 주소창 높이 변화 확인.
- 모바일 목차가 스크롤 시 언제 고정되는지는 정적 이미지로 검증 불가: 위 동작은 **사용자가 합의한 인터랙션 요구사항**이며 구현 테스트가 필수.

### 5.4 본문 이미지와 데이터 진실성
- 연구 도판에는 `figure`/`figcaption`, 원문/라이선스/캡션. 진짜 도판이면 `contain`을 우선하고 정보가 잘리는 `cover` 금지.
- 4개 비교 도판은 PC에서 4열, 모바일은 가독성에 따라 2×2 또는 명시적인 가로 스크롤. 축소로 텍스트가 읽히지 않으면 확대보기 제공.
- 시안에 있는 `92%`, `70% 단축`, 예시 DOI, 대학명은 **검증 전 시각용 샘플**. 원문 근거가 없는 경우 삭제 또는 `예시 데이터` 명시.

## 6. AI 트렌드 상세 (`/trends/[id]`) — 동일한 ArticleLayout

- 상세 템플릿, 3열/모바일 목차/30초 요약/메타·캡션·우측 패널 스타일은 연구사례와 **동일**.
- 바뀌는 것은 콘텐츠: `기술이 등장한 배경 / 연구자가 알아야 할 핵심 / 작동 원리 / 활용 연구 사례 / 제약·한계 / 관련 자료`.
- 요약 항목 제목은 콘텐츠에 맞게 변형 가능하나 4항목 구조는 유지. 트렌드에 실제 연구 성과가 없으면 수치 성과를 만들어 채우지 않음.
- 시안 v3의 연구실 사진·표·도식은 배치 아이디어일 뿐; 상세 P0의 고급스럽고 차분한 타이포·색·패널 밀도를 그대로 적용.

## 7. 목록 페이지 2종 — **구조만 참고, 시각 스타일 재설계**

### 7.1 사례 목록 (`/cases`)
- 참조 구조: `브레드크럼 → 페이지 타이틀/리드 → 선택적 대표 사례 → 필터/검색/정렬 → 카드 목록 → 페이지네이션 → 연구자 인터뷰/관련 콘텐츠 → 푸터`.
- 목록의 대형 히어로는 랜딩 히어로를 복사하지 않음. 대표 사례는 **흰/옅은 라벤더 표면의 2열 콘텐츠 + 의미 있는 연구 이미지**로 구성(제안).
- 카드의 **최종 외형은 랜딩의 최신 인사이트 카드**: 이미지 상단, 작은 분류/분야 메타, 굵은 네이비 제목 2행, 보조 요약 2~3행, 날짜/동작 하단.
- PC 3열, 태블릿 2열, 모바일 1열. 카드 이미지는 16:9 시작값, 제목·이미지 높이·패딩·하단 메타 기준선 동일.
- 카테고리 칩은 1행에서 넘치면 줄바꿈 또는 모바일에서 가로 스크롤(양 끝 그라데이션/스크롤 힌트 포함). 선택은 텍스트와 시각 상태 동시 표시.
- 기존 WHAT THE LAB의 세리프 대제목·베이지 배경·검정 배너·장식용 원 그래픽을 가져오지 않는다.

### 7.2 AI 트렌드 목록 (`/trends`)
- 사례 목록과 `PageHeader`, `FeaturedArticle`, `ArticleCard`, `FilterChip`, `Pagination` 공유.
- `AI 트렌드` 유형 라벨만 절제된 보조 강조색 후보. 전체 카드에 주황 배경을 쓰지 않음.
- 콘텐츠: 주제/기술명 → 연구자가 얻는 의미 → 출처·발행일. 최신 동향이라는 이유만으로 검증되지 않은 성능·출처 생성 금지.
- 카드의 메타·높이·그리드·이미지 비율은 사례 목록과 동일. 같은 화면에서 두 콘텐츠가 혼합되어도 하나의 제품처럼 보여야 함.

## 8. AI 전문가 목록 (`/experts`) — 정보 구조 참조

- 시안/PDF에서 참고할 내용: 키워드 검색, `무엇을 맡길까요?`, `어떤 연구 분야인가요?`, Availability 필터, 정렬, 전문가 프로필 카드.
- 외형: 흰색 카드, 네이비 이름/전문영역, 작은 보라/중립 태그, 라벤더 보조 영역, 얇은 테두리. **v3 시안의 크기/구성은 검토용**, 최종 타이포/간격/버튼은 P0 기준.
- 카드 정보 우선순위: 이름·역할 → 1문장 전문성 → 신규 협업 가능 여부(상태 텍스트) → 관련 연구 분야 → 핵심 기술 → 검증된 프로젝트 경험 → `프로필 보기`.
- 협업 요청 버튼은 `docs/product/MVP_SCOPE.md`의 직접 요청 경로에 해당할 수 있으나, 실제 라우트·로그인 처리와 데이터 계약 확인 전에는 동작을 완성으로 표시하지 않는다.
- `Availability`와 프로젝트 진행 상태는 다른 값. 진행 중인 프로젝트 수만 보고 자동으로 참여 불가 처리 금지.
- PC 3열은 텍스트가 너무 빽빽하면 2열로 변경 가능(Review); 모바일 1열. 기술 태그는 최대 2행 + 나머지 개수 표기 제안.
- v3의 `저장`, 가상 별점, 근거 없는 인증/학위/경력 수치를 그대로 구현하지 않는다.

## 9. AI 전문가 상세 (`/experts/[id]`) — 정보 구조 참조

- 상단: 프로필 이름·역할·연구 전문 분야·짧은 자기소개·Availability.
- 본문: 연구 경험 타임라인 → 대표 과업/성과 → 핵심 기술·활용 분야 → 협업 조건 → 검증된 경력/학력·외부 링크.
- 오른쪽 정보 패널(넓은 화면): 협업 가능 조건, 핵심 역량, 실제 요청 CTA. 본문보다 과도하게 강조하지 않는다. 모바일에서는 본문 다음 또는 상단 요약 직후 배치하되 CTA가 콘텐츠를 가리지 않게 함.
- 후기·평가: `docs/product/MVP_SCOPE.md`에 완료 협업 기반 양방향 평가가 있지만 **실제 완료 프로젝트 데이터가 있을 때만** 표시. 샘플 평점·허위 리뷰 금지.
- 협업 조건/보상은 정보만 표시. 결제·계약·정산 플로우는 추가하지 않음.

## 10. 구현 품질을 떨어뜨리는 패턴과 해결책

| 구현에서 흔한 문제 | 원인 | 수정 기준 |
|---|---|---|
| 디자인은 풍부한데 실제 페이지가 평면적 | 히어로 원본 에셋 누락, 배경 레이어 생략 | 실제 에셋 확보/레이어 구조 분리; 단순 스톡사진으로 대체 금지 |
| 카드마다 제목 위치·높이가 다름 | 콘텐츠 길이·이미지 비율 제각각 | 카드 그리드 `grid-auto-rows`, 동일 이미지 비율, footer `margin-top:auto` |
| 글자 느낌이 시안과 다름 | 웹폰트 미적용/가중치 누락/줄바꿈 차이 | 실제 렌더링 폰트·font-weight·line-height·letter-spacing 확인 |
| 화면이 장난감처럼 보임 | 라운드/그림자/그라데이션 과잉 | P0 기준 작은 radius, 얇은 border, 희미한 shadow만 |
| 연구 콘텐츠가 가짜처럼 보임 | 이미지와 논문/연구 분야 불일치 | 주제 일치 이미지, 출처·캡션, 검증 전 샘플 표시 |
| 모바일 상세가 읽기 힘듦 | PC를 비율 축소, TOC 겹침 | 콘텐츠 재배치, 읽기 폭, sticky 상태 검수 |
| 동일한 화면인데 컴포넌트가 제각각 | 각자 페이지에서 Tailwind 임의값 사용 | 공통 컴포넌트와 중앙 토큰 사용, PR에서 스타일 차이 지적 |

## 11. 개발 수용 기준 (Acceptance Criteria)

- [ ] `1440×900`, `768×1024`, `390×844` 실제 브라우저 스크린샷을 PR에 첨부했다(가능하면 320px 추가).
- [ ] 기준 이미지와 **동일한 가로 폭/줌/폰트 로딩 완료 상태**에서 비교했다.
- [ ] 랜딩 헤더·히어로·탐색 카드·인사이트·인터뷰의 위치와 상대 크기가 P0와 크게 다르지 않다.
- [ ] 사례 상세 3열/모바일 1열, 요약 4→1, 우측 정보 이동이 동작한다.
- [ ] 모바일 TOC 5상태와 현재 섹션 갱신·앵커 오프셋·복귀를 실제 스크롤로 확인했다.
- [ ] 사례/트렌드 목록과 전문가 화면은 **구조만** 보조 시안에서 가져왔고 P0의 색·서체·카드/버튼 스타일을 사용했다.
- [ ] 에셋은 실제 출처/허가/고해상도 원본을 확인했다. 시안 전체 PNG를 잘라 UI 에셋으로 사용하지 않았다.

- [ ] 구현 범위와 MVP+ 기능을 혼동하지 않았고, 결정 대기 사항을 PR에 적었다.
