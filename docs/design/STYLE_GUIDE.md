# LabBridge — UI/UX 디자인 및 구현 스타일 가이드

> 버전: 1.0 통합 검토본 · 2026-10-09  
> 병합 근거: `docs/archive/design/STYLE_GUIDE_ADDENDUM.md` 전체 검토 + 랜딩·사례 상세 승인 방향 + 기존 목록 시안(구조만 참조)  
> **적용:** 디자인·프론트엔드 UI 기준. 코드 작성 규칙은 `docs/development/CODING_STYLE.md`를 따른다. 화면별 상세 지시와 검수는 `docs/design/SCREEN_DESIGN_SPECS.md`, `docs/design/DESIGN_QA_CHECKLIST.md`를 따른다.  
> **중요:** 이 문서의 이미지 기반 픽셀/색상 수치는 **구현 출발점(제안)**이다. Figma 원본 값이나 실제 디자인 승인을 대체하지 않는다.

## 0. 문서 사용법과 우선순위

1. `docs/product/MVP_SCOPE.md`, 최신 팀 의사결정 문서가 **기능 구현 범위**를 결정한다.
2. **시각 디자인 기준**은 최신 LabBridge 랜딩 이미지와 `LabBridge 암세포 분석 연구 페이지` 이미지다.
3. 구형 `WHAT THE LAB` 사례 목록 이미지는 **정보구조·콘텐츠 배열·PC/모바일 전환**만 참고한다. 그 이미지의 글꼴, 배경색, 브랜드, 카드 스타일, 장식 요소는 복사하지 않는다.
4. `docs/archive/design/STYLE_GUIDE_ADDENDUM.md`의 승인 관리·콘텐츠 신뢰성·목차 동작·컴포넌트 재사용·접근성·PR 검수 원칙을 통합했다.
5. 디자인 가이드는 **새 기능을 승인하는 문서가 아니다.** 아직 개발 범위 밖인 화면은 디자인 설계/Mock에 한정한다.
6. 실제 코드가 있으면 기존 공통 컴포넌트·테마·타입을 먼저 조사한다. 문서 예시를 이유로 정상 코드를 무조건 교체하지 않는다.

### 0.2 화면별 승인 상태

| 화면 | 현재 기준 | 적용 정책 |
|---|---|---|
| 랜딩 | Approved direction / 세부 수치 Review | 시각적 기준점. 구조·인사이트 상단 배치 유지 |
| 연구 협업 사례 상세 | Approved direction / 실제 상호작용 Review | 상세 템플릿 기준점 |
| AI 트렌드 상세 | Approved direction(공통 템플릿) | 섹션 내용만 유형별 변경 |
| 연구 사례 목록 | Review | 구형 시안 구조만 가져와 새 디자인 시스템으로 재구성 |
| AI 트렌드 목록 | Review | 사례 목록 공통 UI를 재사용 |
| AI 전문가 목록/상세 | Review | Figma/PDF는 정보 구조 참조, 시각은 P0 기준 |
| 로그인/회원가입 | Review | 요구사항과 실제 Figma 확인 전 임의 확정 금지 |

상태 값: `Approved`, `Review`, `Proposed`, `Deferred`. 정적 이미지에 보이는 UI는 **실제 동작을 검증한 증거가 아니다.**

## 1. 제품 인상과 디자인 원칙

**키워드:** 신뢰할 수 있는 연구 플랫폼 / 차분한 에디토리얼 / 현대적 AI 기술 / 읽기 쉬운 연구 콘텐츠 / 절제된 고급감.

- 밝은 화이트·아주 연한 쿨그레이 바탕, 짙은 네이비 텍스트, 보라 계열을 핵심 인터랙션에 제한적으로 사용한다.
- **랜딩**은 이미지와 명료한 탐색 경로로 서비스를 발견하게 한다. **상세**는 연구 내용을 읽고 근거를 확인하도록 정보 밀도를 관리한다.
- 카드마다 서로 다른 강한 배경색, 의미 없는 3D 아이콘, 과도한 그림자, 네온 글로우, 무분별한 그라데이션을 금지한다.
- 연구 이미지에는 반드시 설명적 역할이 있어야 한다. 현미경/논문/노트북 같은 진부한 장식만으로 AI와 연구를 표현하지 않는다.
- 랜딩 히어로는 시각적 풍부함을 허용하되, 본문과 목록에는 그 수준의 장식을 반복하지 않는다.
- 실제 논문 결과를 설명하는 이미지와 장식용 AI 생성 이미지를 명확히 구분한다.

## 2. 디자인 토큰 — 권장 시작값 (미확정)

**원칙:** 아래 숫자는 제공된 1536×1024 시안에서 시각적으로 추정한 **초기 구현 가설**이다. 디자인 승인 시 Figma 수치로 교체한다. 모든 실제 값은 `frontend`의 CSS 변수/Tailwind 테마 한 곳에만 둔다.

### 2.1 색상

| 토큰 | 초기 권장값 | 사용처 |
|---|---|---|
| `--color-brand` | `#5036F4` | 주요 CTA, 활성 링크, 현재 목차, 강조 |
| `--color-brand-hover` | `#4126D9` | 주요 CTA hover |
| `--color-ink` | `#101C3C` | 페이지 제목, 본문 주요 텍스트 |
| `--color-text-secondary` | `#51607D` | 설명, 메타데이터 |
| `--color-text-muted` | `#75809A` | 보조 라벨·날짜 |
| `--color-page` | `#F8F9FD` | 기본 페이지 배경 |
| `--color-surface` | `#FFFFFF` | 카드, 본문 표면 |
| `--color-surface-soft` | `#F3F2FF` | 핵심 요약, 선택 강조 |
| `--color-border` | `#E4E8F2` | 카드·입력·구분선 |
| `--color-trend-accent` | `#F26745` | 트렌드의 **작은 분류 라벨만**; 확정 전 변경 가능 |
| `--color-expert-accent` | `#087E83` | 전문가의 **작은 분류 라벨만**; 확정 전 변경 가능 |

**주의:** `--color-brand` 등 HEX는 확정값이 아니다. 대비 기준(일반 텍스트 4.5:1, 큰 텍스트 3:1)을 확인한 뒤 승인한다. 색상만으로 유형이나 상태를 구분하지 않는다.

### 2.2 타이포그래피

- 한글 본문 기본: `Pretendard` 또는 팀에서 승인한 한글 웹폰트 + 시스템 폴백. 폰트 파일을 외부에 임의 재배포하지 않는다.
- 영문 브랜드/숫자: 본문과 어울리는 산세리프. 연구 상세 제목은 별도의 장식용 세리프를 섞지 않는다.
- 데스크톱 랜딩 H1: **48–56px / 1.14–1.2 / 700–800**. 긴 제목은 2행 내외. 강조 `LabBridge`만 브랜드 컬러.
- 데스크톱 일반 페이지 H1: **34–42px / 1.22 / 700**.
- 기사 상세 H1: **28–34px / 1.25–1.35 / 700** (가독성 우선).
- H2: **22–26px / 1.35 / 700**; H3: **18–20px / 1.45 / 650–700**.
- 본문: **16–17px / 1.75–1.9**; 목록 카드 설명 **14–15px / 1.55–1.7**.
- 메타/캡션: **12–13px / 1.45–1.6**, 충분한 대비 유지.
- 모바일 H1: 랜딩 **32–38px**, 상세 **25–29px**. 본문은 최소 15–16px.
- 한국어 단어가 어색하게 잘리거나 제목이 세 줄 이상 비정상적으로 분할되지 않게 한다. 줄임표는 목록 카드의 설명에만 제한적으로 적용한다.

### 2.3 간격·모서리·그림자

- 간격 스케일: `4, 8, 12, 16, 20, 24, 32, 40, 48, 64, 80px`.
- 화면 컨테이너: 데스크톱 `max-width: 1400px` **권장 가설**, 1536px 화면에서 좌우 약 68–72px. 태블릿 24–32px, 모바일 16–20px.
- 헤더 높이: 데스크톱 약 `56–64px`, 모바일 약 `56px`.
- 카드 반경: 기본 `12px`(범위 10–16), 버튼 `10px`, 입력 `8–10px`, 필터 칩 pill.
- 카드 테두리: `1px solid var(--color-border)`; 기본 그림자는 아주 약하게 (`0 6px 24px rgba(18,32,75,.04)` 수준). **강한 그림자와 진한 테두리를 동시에 사용하지 않는다.**
- 페이지 섹션 간격: 데스크톱 48–72px, 모바일 32–48px. 카드 내부 패딩: 데스크톱 24–32px, 모바일 16–20px.
- 이 수치는 디자인 파일로 검증 전까지 고정값으로 간주하지 않는다.

### 2.4 실제 CSS/Tailwind 구현 예시

```css
/* frontend/src/app/globals.css 또는 프로젝트에서 승인한 토큰 파일 */
:root {
  --color-brand: #5036f4; /* 이미지 기반 추정: 승인 전 */
  --color-ink: #101c3c;
  --color-text-secondary: #51607d;
  --color-page: #f8f9fd;
  --color-surface: #ffffff;
  --color-border: #e4e8f2;
  --layout-content: 1400px;
  --layout-article: 680px;
  --header-height: 60px;
}

/* 토큰을 사용하고 개별 페이지에서 색상/반경을 다시 발명하지 않는다. */
.page-container {
  width: min(calc(100% - 40px), var(--layout-content));
  margin-inline: auto;
}

@media (min-width: 768px) {
  .page-container { width: min(calc(100% - 64px), var(--layout-content)); }
}
```

Tailwind 버전에 따라 `@theme` 또는 `tailwind.config` 매핑 방법이 달라질 수 있다. **설치된 버전을 확인하고 한 방식으로만 연결한다.** 예시 코드를 그대로 붙여 넣기 전에 실제 프로젝트 구조를 확인한다.

## 3. 공통 컴포넌트 계약

| 컴포넌트 | 시각 규칙 | 필수 동작/상태 |
|---|---|---|
| `SiteHeader` | 흰색·얇은 하단 경계, 좌측 로고, 중앙/우측 탐색, 작은 인증 CTA | 현재 경로 강조, 키보드 포커스, 모바일 메뉴 열기/닫기 |
| `SiteFooter` | 조용한 정보 계층, 서비스명·링크 | 올바른 링크/반응형 |
| `PageContainer` | 화면 공통 좌우 정렬선 | 브레이크포인트별 폭 조절 |
| `Button` | primary 보라, secondary 흰색+테두리, text 링크 | hover/focus/pressed/disabled/loading; 클릭 대상 ≥44px 권장 |
| `Breadcrumb` | 작은 보조 텍스트, 과한 색 금지 | 현재 페이지 `aria-current`, 긴 이름 줄임 |
| `ArticleCard` | 이미지 비율 고정, 제목 2행, 요약 2–3행, 메타 하단 정렬 | 카드 전체 링크의 접근성, 이미지 fallback |
| `ArticleMeta` | 날짜·분야·출처의 고정 순서 | 값이 없으면 지어내지 않음 |
| `KeywordTag` | 연한 바탕의 작은 칩 | 선택형 필터와 일반 정보 태그를 구분 |
| `FilterChip` | 선택 전/후 대비 명확, 선택 상태에만 강조 | `aria-pressed`, 필터 해제·초기화 |
| `Pagination` | 작은 숫자/화살표, 활성 페이지만 강조 | 이전/다음 disabled, URL과 동기화 |
| `ExpertCard` | 인물·역량·연구경험·참여 가능 여부 순서 | availability와 프로젝트 진행 상태 분리 |
| `ProfileSection` | 정보 제목·본문의 일관된 간격 | 빈 값·링크 검증 |
| `ArticleLayout` | PC 3열/모바일 1열, 본문 가독성 | 좌측/모바일 목차, 우측 보조 정보 |
| `TableOfContents` | 선택 섹션 보라/좌측 선, 나머지 중립 | sticky, 앵커 이동, 현재 섹션 갱신 |
| `SourceList` | 저자·제목·발행처·연도·URL/DOI | 검증된 외부 링크, 출처 표시 |
| `ExpertCTA` | 기사 말미 또는 우측의 조용한 연결 CTA | MVP 범위와 라우트 존재 여부 확인 |
| `Loading/Empty/ErrorState` | 화면의 여백과 톤을 유지 | 재시도, 오류 설명, 스켈레톤 레이아웃 유지 |

**중복 금지:** 기존 이름이 다르더라도 동일한 컴포넌트가 있다면 재사용한다. 공통화는 실제 시각과 동작이 같을 때만 한다. 화면별로 `rounded-*`, `shadow-*`, `text-*`를 무작위 조합해 카드 모양을 바꾸지 않는다.

## 4. 랜딩페이지 — 최종 시각 기준

### 4.1 데스크톱 정보 구조

1. **상단 헤더:** 로고 + `LabBridge`, 홈 / AI 연구 협업 사례 / AI 트렌드 / AI 전문가 찾기, 검색 아이콘(실제 검색 동작이 확정된 경우), 회원가입·로그인. 현재 메뉴는 가느다란 보라색 하단 표시.
2. **히어로:** 좌측 소형 영문 eyebrow `RESEARCH × AI × COLLABORATION` → 강한 2행 제목 `연구의 질문이 / AI와 만나는 곳, LabBridge` → 2행 설명 → 보라색 `지금 시작하기` CTA. **CTA 목적지 미확정**이므로 임의로 가입이나 프로젝트 생성에 연결하지 않는다.
3. **히어로 우측 비주얼:** 단순한 사진 한 장이 아니라 바이오 단백질 구조/의료영상/기후 연구를 나타내는 다층 연구 이미지 + 얇은 데이터 연결선 + 작고 절제된 분야 라벨. 주제는 연구 × AI의 다학제 연결을 표현해야 한다.
4. **세 개 탐색 카드:** `AI 연구 협업 사례`, `AI 트렌드`, `AI 전문가 찾기`. 3열, 카드마다 콘텐츠 관련 배경 이미지·부드러운 오버레이·분류 칩·작은 원형 화살표. 카드 제목/설명/CTA 정렬선 동일.
5. **최신 인사이트:** 3개 카드 그리드(사례·트렌드 혼합), 좌측 이미지, 제목/요약/분류/날짜. 우측에는 **연구자 인터뷰** 패널을 독립적으로 배치. `전체 보기`는 콘텐츠 목록으로 이동(구체 라우트 합의 필요).
6. 하단 푸터. 시안 밖의 섹션을 임의로 추가하거나 인사이트를 하단으로 이동하지 않는다.

### 4.2 랜딩 구현에서 자주 발생하는 품질 저하

- 히어로를 배경 이미지 1장으로 대체하여 텍스트 대비·다층 연구 비주얼이 사라지는 것 금지.
- 카드 배경 이미지가 흐리거나 텍스트와 겹치면 이미지 위에 국소적인 밝은 오버레이를 사용한다. 불투명도를 무작정 올려 이미지 의미를 없애지 않는다.
- 카드별 높이, 제목 baseline, 화살표 원형 버튼의 위치, 하단 태그 라인이 달라지지 않게 한다.
- 헤더·히어로·탐색 카드·인사이트의 좌우 컨테이너 기준선은 일치시킨다.
- 이미지는 실제 원본 에셋을 확보한다. 시안 PNG에서 일부를 잘라 재사용하면 해상도·텍스트·저작권·반응형 문제가 생길 수 있다. **원본 에셋 없으면 승인된 대체 에셋을 요청하고 임의 유사 이미지를 끼우지 않는다.**
- 랜딩만 그림자가 과하거나 과도한 애니메이션을 넣어 다른 페이지와 톤이 어긋나지 않게 한다.

### 4.3 모바일 랜딩

- 상단 로고, 검색(기능 확정 시), 메뉴 버튼. 메뉴는 접근 가능한 drawer/overlay. 데스크톱 내비게이션 단순 숨김만 하지 않는다.
- 히어로는 텍스트 먼저, 비주얼은 텍스트와 충돌하지 않도록 아래 또는 뒤에 제한적으로 배치한다.
- 세 개 탐색 카드는 1열로 배치, 터치 대상 확보, 배경 이미지의 주제 유지.
- 최신 인사이트는 1열, 인터뷰 패널은 그 뒤에 배치. 정보 순서 자체는 유지한다.

## 5. 인사이트 상세 — 사례/트렌드 공통 템플릿

### 5.1 PC 3열 배치

```text
[공통 SiteHeader]
[Breadcrumb]
┌───────────────┬──────────────────────────────────┬──────────────────┐
│ 왼쪽 목차      │ 중앙: 기사 제목·메타·30초 요약·본문  │ 오른쪽 연구 정보  │
│ sticky        │ 그림·캡션·근거·관련 콘텐츠         │ 관련 AI 기술     │
│ 현재 섹션 강조 │                                  │ 관련 콘텐츠/CTA  │
└───────────────┴──────────────────────────────────┴──────────────────┘
```

- 전체 폭은 랜딩 컨테이너를 따르되 **본문 읽기 폭은 약 620–720px**를 우선한다.
- 좌측 목차 약 150–180px, 중앙 본문 최소 600px 권장, 우측 패널 약 230–270px, 열 간격 약 24–32px. **제공된 이미지 기준 추정값**이며 1200px 이하에서는 3열을 무리하게 유지하지 않는다.
- 제목·키워드·메타는 중앙 상단에서 하나의 정보 단위로 읽힌다. 메타 사이 구분선·아이콘은 작은 보조 요소다.
- 우측 `연구 정보`는 분야/기술/데이터/기관/발표일/원문 링크/DOI **존재하는 항목만**. 출처 없는 가짜 기관·DOI를 채우지 않는다.
- `관련 AI 기술`은 쉬운 설명 + 기술 상세로 가는 실제 링크. `관련 콘텐츠`는 동일 카드 규칙의 간결한 리스트.
- 우측 패널이 중앙 본문보다 강하게 시선을 빼앗지 않도록 배경은 흰색, 얇은 테두리, 작은 타이포를 사용한다.

### 5.2 상단 콘텐츠 순서

1. Breadcrumb
2. `AI 연구 협업 사례` 또는 `AI 트렌드` 유형 라벨, 분야·기술 라벨
3. H1, 2–3행 이내의 요약 리드
4. 기관/저자, 발행일, 읽는 시간(산출 가능 시), 원문 링크
5. **30초 핵심 요약**: 연구 문제 / AI 역할 / 주요 결과 / 적용 가능성
6. 기사 본문
7. 한계·적용 조건 / 출처·참고문헌 / 관련 AI 기술 / 전문가 연결 / 관련 콘텐츠

### 5.3 30초 핵심 요약

- 상세 이미지에서 보이는 **연한 라벤더 외곽 + 흰색 내부 4칸** 구조를 기준으로 한다.
- 4개 항목은 아이콘, 짧은 제목, 1–2문장. 아이콘은 일관된 선형 스타일(보라색)로 통일하고 그림/이모지를 섞지 않는다.
- 데스크톱: 4열, 동일 높이. 태블릿: 2×2. 모바일: 1열 또는 시안처럼 4개 세로 행.
- 모바일에서 요약 문장이 잘리지 않도록 고정 높이를 사용하지 않는다.
- `주요 결과`에는 **원문으로 검증된 값만** 표시한다. 예시 화면의 `92%` 등을 실제 연구 성과로 복사하지 않는다.

### 5.4 본문·이미지·캡션

- 섹션 번호(`01.`)는 작은 보라색, 섹션 제목은 네이비. H2 간격은 위 40–56px/아래 16–24px 권장.
- 본문 한 줄이 지나치게 길지 않도록 본문 최대 폭을 유지한다. 긴 단락은 3–5문장 단위로 자연스럽게 구분한다.
- 현미경 이미지 4개 비교, 처리 흐름도 등은 **실제 연구와 직접 관련된 도판**으로 구현. PC 4열 비교 → 모바일 4개 썸네일 또는 가로 스크롤(의도적으로 안내한 경우만) 등 별도 설계.
- 이미지 비율은 자료 특성에 따라 `object-fit: contain` 우선(연구 도판의 중요한 정보가 잘리면 안 됨). 장식용 썸네일은 `cover` 가능.
- 모든 도판에 번호·설명·출처·라이선스 확인 상태를 표기한다. 캡션은 이미지 아래에 중앙 또는 좌측 정렬을 일관되게 사용한다.
- `실험 결과`, `LabBridge 해석`, `연구 적용 아이디어`를 별도 문장 또는 라벨로 구분한다.
- 모바일에서 도판은 가로 폭에 맞추고 필요한 경우 비교 대체 UI를 제공한다. 이미지 안의 글씨가 읽히지 않으면 원본 확대 링크를 제공한다.

### 5.5 유형별 콘텐츠 구조

| 연구 협업 사례 | AI 트렌드 |
|---|---|
| 연구 배경·문제 | 기술 소개·등장 배경 |
| 기존 방식의 한계 | 기존 기술과의 차이 |
| AI 적용 방법·데이터 | 쉬운 작동 개념 |
| 검증 결과·평가 조건 | 실제 활용 사례·근거 |
| 한계·적용 조건 | 연구 활용 분야·제약 |
| 출처·관련 기술 | 출처·관련 기술 |

**템플릿은 하나**, 콘텐츠 타입에 따라 섹션 제목·우측 메타 필드·CTA 문구만 바뀐다. 트렌드라고 해서 완전히 다른 컬러풀 레이아웃을 만들지 않는다.

### 5.6 목차 sticky — 실제 구현 요구사항

**데스크톱**
- 목차는 본문 왼쪽. `position: sticky; top: calc(var(--header-height) + 24px)` 수준으로 고정 헤더 아래에 둔다.
- 현재 읽는 섹션을 강조. 항목 클릭 시 해당 제목으로 이동하고 브라우저 히스토리/해시를 적절히 반영한다.
- 목차가 너무 길면 목차 내부만 스크롤 가능하게 하고, 본문보다 높게 늘어나지 않게 한다.

**모바일**
- 목차는 **처음에는 본문 흐름에 포함**되며, 상단에 도달한 이후 헤더 바로 아래에서 접힌 1행 sticky 목차가 된다.
- 접힌 상태: `목차` + 현재 읽는 섹션명 + 펼침 버튼. 펼치면 전체 섹션 리스트가 보인다.
- 선택하면 해당 H2로 이동, 목차 접힘, 현재 섹션 갱신. 키보드/스크린리더에서 열림 상태(`aria-expanded`) 확인.
- `scroll-margin-top: calc(var(--header-height) + var(--toc-height) + 16px)`로 제목이 가려지지 않게 한다.
- **sticky는 article layout 영역 안에서만** 동작하도록 범위를 제한해 푸터 위에 계속 떠 있지 않게 한다.
- 구현 방식(IntersectionObserver, scroll events 등)은 코드 구조와 성능에 맞게 결정하되, 리스너 정리·스크롤 떨림·iOS Safari를 검증한다.
- `prefers-reduced-motion` 사용자는 부드러운 스크롤 애니메이션을 강제하지 않는다.

## 6. 목록 — 구형 시안의 구조만 사용

### 6.1 공통 목록 페이지 구조

1. 공통 헤더/브레드크럼
2. 페이지 제목·소개문(랜딩/상세와 같은 타이포·색)
3. 선택적 대표 콘텐츠(시안에 존재하더라도 승인 여부 Review)
4. 분야/기술 필터 + 결과 개수 + 정렬
5. 콘텐츠 그리드 또는 리스트
6. 페이지네이션/더 보기(정책 승인 필요)
7. 인터뷰/추천·최근 콘텐츠(실제 필요와 구현 범위 확인)
8. 공통 푸터

- 구형 시안의 큰 세리프 제목, 베이지 바탕, 검은 직사각형 히어로, 기존 WHAT THE LAB 로고, 장식성 원형 그래픽은 **이식 금지**.
- 목록 H1, 카드, 칩, 간격, 구분선, 그림자, 버튼은 **랜딩의 인사이트 카드 + 상세의 요약/보조 패널**에서 가져온다.
- 콘텐츠 카드 이미지 비율은 데스크톱 약 `16:9` 권장. 그리드 3열(넓은 화면) → 2열(태블릿) → 1열(모바일).
- 카드 이미지와 제목 사이의 간격·메타 위치·카드 높이를 통일한다. 제목 2행, 요약 2–3행 제한 후 상세에서 전체 노출.
- 모든 필터는 실제 데이터와 연결하고, URL 검색 파라미터에 상태를 반영할지 팀에서 확정한다. 동작하지 않는 필터 UI를 완성품처럼 배치하지 않는다.

### 6.2 AI 연구 협업 사례 목록

- 콘텐츠 우선순위: 연구 분야 → 제목 → 해결하려던 문제 → 사용 AI 기술 → 검증된 성과/제약 → 출처/발행일.
- 상단 대표 사례는 1개를 크게 보여주는 구조를 **제안**할 수 있으나, 랜딩 히어로를 복제하거나 어두운 남색 배경의 구형 배너를 그대로 옮기지 않는다.
- 필터: 연구 분야, AI 기술, 키워드(실제 데이터 필드 존재 시). `전체`를 기본 선택.
- 카드 클릭 → 해당 연구 사례 상세. 빈 목록/오류/로딩/다음 페이지 상태 필수.
- 실재 연구 근거 없는 임의 논문·실험 성과를 실제 콘텐츠처럼 게시하지 않는다.

### 6.3 AI 트렌드 목록

- 사례 목록과 `PageHeader`, `ArticleCard`, `FilterChip`, `Pagination` 재사용.
- 카드에 `AI 트렌드` 라벨과 기술 주제/연구 활용 가능성을 표시. 기술명 자체가 연구 결과인 것처럼 표현하지 않는다.
- 구분 포인트는 작은 라벨·보조 색상 정도로 제한; 본문·카드 전체를 주황색으로 바꾸지 않는다.
- 최신/주목/분야별 정렬은 실제 정책 승인 후. 사례와 같은 구조로 읽히도록 한다.

### 6.4 AI 전문가 목록

- 기존 Figma/PDF에서 **정보 항목과 필터 구조만** 참고. 전문가 카드도 랜딩·상세와 동일한 백색 카드/네이비 텍스트/보라 CTA 시스템을 따른다.
- 상단: `AI 전문가 찾기` 제목 + 소개 → 목록 내부 키워드 검색 → `필요한 기술·과업`, `연구 분야`, `신규 협업 가능 여부` 필터(기본 기능 승인 여부 확인) → 결과 수/정렬.
- 카드 정보 순서: 이름/역할 → AI 전문 분야 → **Availability** → 관련 연구 분야 경험 → 대표 협업·프로젝트 경험 → 핵심 기술 → 프로필 보기.
- `현재 프로젝트 진행 중`과 `신규 협업 가능`은 서로 다른 정보. 진행 프로젝트가 있다고 신규 요청을 막지 않는다.
- 실제로 제공하지 않는 별점/후기/인증을 만들어 표시하지 않는다. `내 연구로 찾기`는 해당 등록/매칭 흐름의 범위와 연결이 확인될 때만.
- PC 3열 권장(내용 많으면 2열), 모바일 1열. 긴 소개는 2–3줄 제한, 핵심 역량이 상단에 보이게 한다.

### 6.5 AI 전문가 상세

- 상단: 이름·역할·전문 영역·신규 협업 가능 상태 + 연구 적합성을 이해할 수 있는 한 줄 소개.
- 본문: 관련 연구 경험/완료 협업 → 핵심 기술·연구 분야 → 협업 조건/가능 시간 → 경력/학력 → 외부 링크(있는 경우).
- 협업 요청 CTA는 **최신 MVP/도메인 정책상 직접 요청 경로와 연결 가능하지만**, 구체 라우트·로그인 필요 여부·요청 작성 화면의 실제 구현이 확인되기 전에는 동작을 임의 확정하지 않는다.
- 평가 정보는 완료 프로젝트와 연결된 실제 값만. 허위 별점/후기 표시 금지. Availability와 프로젝트 상태 분리.
- 데스크톱에서 프로필 주요 정보와 협업 가능 정보의 우선순위를 명확히 하고, 모바일에서는 CTA가 읽기 흐름을 가리지 않도록 배치한다.

## 7. 반응형·접근성·상태

| 기준 화면폭 | 레이아웃 요구 | 상태 |
|---|---|---|
| 1440px | 랜딩 3카드, 인사이트 3+인터뷰, 상세 3열(공간 확보 시), 목록 3열 | QA 기준 |
| 1024px | 카드 2열 가능, 상세 우측 패널은 본문 아래 또는 숨김 아닌 이동 | 제안 |
| 768px | 헤더 모바일/태블릿 전환 검토, 상세 1열 또는 2열, 목차 전환 | QA 기준 |
| 390px | 1열, 모바일 목차 접힘/sticky, 필터 drawer, 가로 넘침 없음 | QA 기준 |
| 320px | 긴 단어/버튼/태그의 overflow 방지 | 보조 QA |

- 브레이크포인트는 `640 / 768 / 1024 / 1280px`을 초기 후보로 삼되 실제 콘텐츠가 깨지는 지점에서 조정한다.
- 인터랙션 터치 영역 최소 44×44px 권장, 키보드 `:focus-visible`, 모달/메뉴 focus trap 및 Esc 종료, aria-label/expanded, heading 순서 검증.
- 일반 텍스트 대비 4.5:1 이상, 큰 텍스트 3:1 이상 권장. 키보드·화면낭독기·200% 확대에서 읽을 수 있어야 한다.
- 모든 이미지에 목적에 맞는 alt. 장식용 이미지 `alt=""`; 도표에는 핵심 내용을 텍스트로 제공한다.
- 로딩 스켈레톤은 실제 카드와 유사한 크기로 만들어 레이아웃 이동을 줄인다. 빈 결과는 필터 초기화, 오류는 재시도, 인증 오류는 적절한 안내를 제공한다.
- 버튼·링크는 실제 동작이 있어야 한다. **Mock 단계라면 Mock이라고 표시**하고 완성 기능처럼 위장하지 않는다.

## 8. 콘텐츠 신뢰성·이미지 에셋 관리

- 연구사례/트렌드: 원문 유형, 제목, 저자, 발행일, 출처 URL/DOI(있는 경우), 이미지 라이선스 확인 상태를 구조화한다.
- `원문에서 확인된 결과`와 `LabBridge의 해석/적용 아이디어`를 구분한다. 정확도·성능·연구기관을 임의로 생성하지 않는다.
- 이미지 에셋은 `asset_id`, 파일 경로, 출처, 사용 허가/라이선스, alt, 캡션, 사용 위치를 기록한다.
- 랜딩의 히어로용 합성 비주얼은 **장식적 컨셉 이미지**임을 구분하고 실제 실험 결과인 것처럼 표시하지 않는다.
- 목록 썸네일은 기사 주제와 직접 관련되어야 한다. 도표는 가능한 원본·허용된 재제작 도식 사용.
- 이미지 로딩 실패 시 대체 배경/문구를 제공한다. 고해상도 원본·적절한 크롭·`sizes`·이미지 최적화로 화면별 선명도를 확보한다.

## 9. 실제 구현의 디자인 충실도 검수 (필수)

### 9.1 PR 전 스크린샷 비교

1. **같은 viewport**에서 기준 시안과 구현 화면을 나란히 비교: 데스크톱 1440×900, 태블릿 768×1024, 모바일 390×844 (브라우저 배율 100%).
2. 먼저 **큰 레이아웃**을 맞춘다: 헤더 높이, 컨테이너 시작점, 히어로 높이, 카드 행, 3열 폭, 섹션 순서.
3. 그다음 **타이포**: H1 줄바꿈·두께·행간, 카드 제목 2행, 본문 읽기 폭, 날짜/태그 계층.
4. 그다음 **에셋**: 주제 일치, 해상도, 이미지 비율, 크롭, 캡션, 대비.
5. 마지막 **디테일**: radius, border, shadow, 아이콘 크기, 칩 간격, hover/focus/disabled.
6. 모바일 상세에서 스크롤 중 **헤더와 접이식 목차가 겹치지 않는지**, 섹션 이동 후 제목이 가려지지 않는지, 푸터 앞에서 sticky가 종료되는지 확인한다.
7. 확인 결과를 PR에 `기준 이미지 / 구현 캡처 / 차이점 / 수정 후 캡처 / 남은 미확정 사항` 순서로 남긴다.

### 9.2 실패 판정 사례

- 구형 WHAT THE LAB 목록의 배경색/제목 폰트/배너를 그대로 사용했다.
- 랜딩 히어로 이미지가 사라지거나 관련 없는 일반 AI/현미경 사진으로 바뀌었다.
- 공통 헤더/컨테이너의 정렬선이 페이지마다 다르다.
- 동일한 카드인데 페이지마다 다른 그림자/라운드/타이포를 사용한다.
- 상세 본문이 지나치게 좁거나 넓고 우측 패널이 주 콘텐츠보다 강하다.
- 모바일 목차가 헤더를 가리거나 현재 섹션을 갱신하지 않는다.
- 실제 검증되지 않은 논문 수치/후기/기관/링크가 화면에 존재한다.
- 버튼이 클릭되지 않거나 필터가 화면만 바뀌고 결과에는 반영되지 않는다.

### 9.3 최종 수용 체크리스트

- [ ] 승인 상태·기준 시안 링크/파일명이 기록되어 있다.
- [ ] 랜딩·상세가 같은 브랜드/타이포/색/여백 체계를 쓴다.
- [ ] 구형 목록의 **정보 구조만** 사용했고 시각은 신규 시스템으로 통일했다.
- [ ] 사례·트렌드 상세가 공통 템플릿을 사용한다.
- [ ] 공통 컴포넌트와 토큰을 재사용하고 임의 하드코딩을 피했다.
- [ ] PC 1440px, 태블릿 768px, 모바일 390px 캡처 비교를 남겼다.
- [ ] 헤더/목차/필터/페이지네이션/CTA의 실제 동작을 검증했다.
- [ ] 로딩·빈 결과·오류·포커스·모바일 overflow를 확인했다.
- [ ] 출처/날짜/성과/이미지 라이선스가 콘텐츠 사실과 일치한다.
- [ ] 디자인 미승인 항목이나 범위 밖 기능을 임의 구현하지 않았다.

## 11. MVP 범위와 디자인 시안의 충돌·결정 대기

## 13. 시안 충실도를 보장하는 구현 계약 (필수)

- 화면 개발자는 `docs/design/SCREEN_DESIGN_SPECS.md`의 해당 화면 섹션을 **코드 작성 전에** 읽는다.
- 각 화면은 레이아웃/타이포/이미지/디테일의 4단계로 나눠 비교한다. 한 단계가 크게 다르면 다음 단계로 넘어가기 전에 수정한다.
- 시안에서 표현된 고급스러움은 단순한 HEX 복사로 재현되지 않는다. **원본 이미지 에셋, 정확한 크롭, 폰트 가중치, 콘텐츠 밀도, 기준선 정렬, 모바일 콘텐츠 순서**를 함께 맞춘다.
- 기존 목록/전문가 시안에서 시각 요소를 복사하지 않는다. `P0` 랜딩·상세에서 공통 스타일을 도출하고, `P1`에서는 정보 구조만 채택한다.
- `docs/design/DESIGN_QA_CHECKLIST.md`의 1440/768/390px 캡처·차이 기록 없이 UI 작업을 완료로 선언하지 않는다.
- `docs/archive/design/STYLE_GUIDE_ADDENDUM.md`는 본 문서에 병합 완료했다. 원본/병합 위치는 `docs/archive/design/ADDENDUM_MERGE_MAP.md` 참조.

## 14. 인사이트 읽기 보조 — 2026-10-17 로컬 검토안

사용자가 요청한 MatterGen 두 관점의 글, 쉬운 용어 설명, 편집자 노트에 한해 적용한다. 팀 전체 최종 디자인 승인이나 챗봇 구현 승인을 의미하지 않는다.

- 기존 P0 3열/모바일 1열, 왼쪽 목차, 상단 이미지·요약을 유지한다.
- 원문 본문은 일반 문단, 편집자 해설은 `연구자에게 주는 의미`, 제안은 `내 연구에 적용한다면`, 한계 판단은 `주의할 점 · 적용의 경계`로 표시한다. 원문의 직접 결론과 편집자 노트를 문구로도 구별한다.
- 해설은 기존 brand-soft, 적용 제안은 expert-soft 배경을 재사용한다. 적용 제안 제목은 충분한 대비를 위해 editorial-application, 주의 박스는 editorial-warning 토큰을 globals.css 한 곳에 정의한다. 본문 전체의 글자색을 바꾸지 않고 라벨·왼쪽 선·연한 배경을 함께 사용한다.
- 본문은 16px/1.85로 읽기 크기를 확보한다. 용어는 첫 등장 문맥에서 풀고 해당 섹션의 native `details/summary`에서 정의·예시·한계를 펼친다. hover 전용 UI, 가짜 챗봇 버튼, 외부 요청은 추가하지 않는다.
- 두 글은 `같은 주제, 다른 관점` 링크로 연결한다. 같은 연구를 독립적인 연구 성과 두 건으로 표시하지 않는다.
- 검증 및 남은 범위: `docs/qa/INSIGHT_READING_EXPERIENCE_2026-10-17.md`.
