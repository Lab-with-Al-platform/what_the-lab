# MySQL → PostgreSQL 전환 정리

> 후속 통합: [팀 공통 DB 안내](SHARED_DATABASE_GUIDE.md)가 연결 설정의 최신 기준입니다. DATABASE_URL이 있으면 회원·인사이트 모두 그 값을 사용합니다. 이 문서의 기존 MySQL 삭제 예시는 통합의 필수 절차가 아닙니다. **기존 데이터·볼륨은 명시적 삭제 합의와 백업 없이 삭제하지 않습니다.**

> 2026-10-21, 회원·내 이력·내 연구 DB를 **MySQL에서 PostgreSQL로** 옮겼습니다.
> 이 문서 하나에 **무엇을 어떤 순서로 바꿨는지**와 **팀원이 내 PC에서 할 일**을 모았습니다.
> 다른 가이드(`SIGNUP_LOGIN_GUIDE.md`, `MY_SPACE_GUIDE.md`)에 남아 있는 MySQL·3309 설명보다 **이 문서가 우선**입니다.

## 0. 한눈에 보기

| 항목 | 전 (MySQL) | 후 (PostgreSQL) |
|---|---|---|
| DB | MySQL 8.4 | **PostgreSQL 17** |
| 컨테이너 이름 | `labbridge-mysql` | `labbridge-postgres` |
| 접속 | `localhost:3309` | **`localhost:5433`** |
| DB 이름 | `labbridge` | `labbridge` |
| 아이디 / 비밀번호 | 각자 `.env`에 정한 값 | **팀원 모두 `admin` / `admin123`** |
| 테이블 만들기 | 004~006은 DBeaver로 직접 실행 | **`docker compose up -d` 하면 001~006 전부 자동** |
| 백엔드 드라이버 | `pymysql` | `psycopg` |

- `admin123`은 **내 PC 안에서만** 쓰는 개발용입니다. `127.0.0.1`에만 열려 있어서 다른 PC는 접속할 수 없고, 배포(Supabase)에는 절대 쓰지 않습니다.
- 포트를 5432가 아닌 **5433**으로 둔 이유: PC에 PostgreSQL을 따로 설치한 사람은 5432가 이미 쓰이고 있어서 충돌합니다.
- API 주소와 응답 모양은 그대로라서 **프론트는 바뀐 게 없습니다.**

### 바뀐 테이블 이름

| 전 | 후 | 이유 |
|---|---|---|
| `user` | `users` | `user`는 PostgreSQL 예약어 |
| `collaboration` | `expert_collab_condition` | 앞으로 만들 **협업 요청**과 헷갈리지 않게 |
| `domain` | `expert_domain` | 연구 쪽 `research_domain`과 짝 |
| `reward` | `expert_reward` | 연구 쪽 `research_reward`와 짝 |
| `expert_able_work.expert_capability` | `expert_able_work.able_work_id` | 다른 표와 같은 컬럼 이름 |

## 2. 무엇을 바꿨나 (작업한 순서대로)

### 1단계. 회원 테이블 SQL — `database/init/001_create_tables.sql`

MySQL 문법을 PostgreSQL 문법으로 바꾸고, `user` → `users`, `expert_capability` → `able_work_id`로 이름을 바꿨습니다.
맨 위에 `updated_at`을 자동으로 바꿔 주는 함수 `set_updated_at()`을 새로 만들었습니다.

| MySQL | PostgreSQL | 의미 |
|---|---|---|
| `SET NAMES utf8mb4;` | 삭제 | PostgreSQL은 기본이 UTF-8. 이 줄이 있으면 오류 |
| `BIGINT NOT NULL AUTO_INCREMENT` | `BIGINT GENERATED BY DEFAULT AS IDENTITY` | 번호 자동 증가 |
| `DATETIME` | `TIMESTAMPTZ` | 시간대(+09:00)까지 저장하는 날짜·시간 |
| `DEFAULT CURRENT_TIMESTAMP` | `DEFAULT now()` | 만들 때 지금 시간 |
| `ON UPDATE CURRENT_TIMESTAMP` | 표마다 `CREATE TRIGGER ... EXECUTE FUNCTION set_updated_at();` | 값이 실제로 바뀐 줄만 `updated_at` 갱신 |
| `COMMENT '설명'` | 줄 끝 `-- 설명` | 설명은 주석으로 |
| `UNIQUE KEY 이름 (...)` | `CONSTRAINT 이름 UNIQUE (...)` | 제약 이름을 붙이는 방식 |

### 2단계. 내 이력·내 연구 테이블 SQL — `004`, `006`

- `004`: 같은 문법 변환 + `domain` → `expert_domain`, `collaboration` → `expert_collab_condition`, `reward` → `expert_reward`
- `006`: 표 이름은 그대로, 문법만 변환
- PostgreSQL은 FK 컬럼에 인덱스를 자동으로 만들지 않아서, `user_id`로 자주 찾는 표(`portfolio`, `career`, `education`, `certificate`, `research`)에 `CREATE INDEX`를 추가했습니다.

### 3단계. 시드 SQL·시드 스크립트 — `002`, `003`, `005` + `database/seed/build_*_seed.py`

- 시드 SQL 3개의 2번째 줄 `SET NAMES utf8mb4;`를 지웠습니다.
- 시드를 다시 만들 때 그 줄이 또 생기지 않게 스크립트 3개에서도 지웠습니다.

### 4단계. DB 실행 설정 — `docker-compose.yml`, `.env.example`

```yaml
services:
  postgres:
    image: postgres:17
    container_name: labbridge-postgres
    environment:
      POSTGRES_USER: admin
      POSTGRES_PASSWORD: admin123
      POSTGRES_DB: labbridge
    ports:
      - "127.0.0.1:5433:5432"
    volumes:
      - postgres_data:/var/lib/postgresql/data
      - ./database/init:/docker-entrypoint-initdb.d:ro
```
- `POSTGRES_*`: 처음 켤 때 이 계정과 DB를 만듭니다.
- `127.0.0.1:5433:5432`: 내 PC의 5433 → 컨테이너 5432. 내 PC에서만 접속됩니다.
- `docker-entrypoint-initdb.d`: DB가 **비어 있을 때 한 번만** `database/init/*.sql`을 이름 순서(001 → 006)대로 실행합니다. 이게 "자동 테이블 생성"입니다.
- `.env.example`의 DB 항목을 위 값과 같게 바꿨습니다.

### 5단계. 백엔드 DB 연결 — `backend/app/config.py`, `backend/app/db.py`

- `config.py`: 기본 포트 `3309` → `5433`
- `db.py`: `pymysql` → `psycopg`

```python
psycopg.connect(
    host=..., port=..., user=..., password=..., dbname=config.DB_NAME,
    row_factory=dict_row,  # 결과를 dict로 (예전 DictCursor)
    autocommit=True,       # 한 줄씩 바로 저장
    connect_timeout=5,     # DB가 꺼져 있으면 5초 안에 오류
)
```
- `transaction()`은 `conn.transaction()`을 쓰도록 바꿨습니다. 블록이 끝나면 저장, 오류가 나면 전부 취소합니다. **쓰는 쪽 코드(`with transaction() as cursor:`)는 그대로입니다.**
- `psycopg`는 원래 `pyproject.toml`에 있어서 새로 설치할 게 없습니다.

### 6단계. 가입 — `user_store.py`, `routers/verification.py`, `routers/researcher.py`, `routers/expert.py`

| 바꾼 것 | 전 | 후 |
|---|---|---|
| 테이블 이름 | `` `user` `` | `users` |
| 방금 만든 번호 받기 | `cursor.lastrowid` | `INSERT ... RETURNING user_id` → `cursor.fetchone()["user_id"]` |
| 있으면 수정, 없으면 추가 | `ON DUPLICATE KEY UPDATE x = VALUES(x)` | `ON CONFLICT (user_id) DO UPDATE SET x = EXCLUDED.x` |
| 묶음 저장 | `conn.begin()` / `commit()` / `rollback()` | `with transaction() as cursor:` |
| TRUE/FALSE 변환 | `bool(row["..."])` 줄 | 삭제 (PostgreSQL은 처음부터 `True`/`False`) |
| 컬럼 이름 | `expert_capability` | `able_work_id` |

### 7단계. 내 이력 — `expert_profile_store.py`, `routers/expert_profile.py`, `routers/expert_portfolio.py`

- 바뀐 테이블 이름 반영 (`expert_domain`, `expert_collab_condition`, `expert_reward`, `able_work_id`)
- 협업 조건 저장: `ON DUPLICATE KEY` → `ON CONFLICT (user_id) DO UPDATE`
- 포트폴리오 추가: `lastrowid` → `RETURNING portfolio_id`
- `expert_history.py`(경력·학력·자격증)는 표 이름이 그대로라 바꾸지 않았습니다.

### 8단계. 내 연구 — `research_store.py`, `routers/researcher_research.py`

- `` `user` `` → `users`, `bool(...)` 변환 줄 삭제
- 연구 추가: `lastrowid` → `RETURNING research_id`

### 9단계. 정리

- `backend/tests/conftest.py`: MySQL을 언급하던 주석 한 줄 수정
- 이 문서 추가

## 4. 앞으로 새 테이블을 만들 때

`database/init/007_...sql`처럼 **다음 번호로 새 파일**을 만들고 PostgreSQL 문법으로 씁니다.

```sql
CREATE TABLE 예시 (
  예시_id     BIGINT       GENERATED BY DEFAULT AS IDENTITY,
  user_id     BIGINT       NOT NULL,
  status      VARCHAR(20)  NOT NULL  DEFAULT 'sent',  -- 설명은 이렇게 주석으로
  created_at  TIMESTAMPTZ  NOT NULL  DEFAULT now(),
  updated_at  TIMESTAMPTZ  NOT NULL  DEFAULT now(),
  CONSTRAINT pk_예시 PRIMARY KEY (예시_id),
  CONSTRAINT fk_예시_user FOREIGN KEY (user_id) REFERENCES users(user_id) ON DELETE CASCADE
);
CREATE INDEX idx_예시_user ON 예시 (user_id);              -- FK 컬럼은 인덱스를 직접
CREATE TRIGGER trg_예시_updated_at BEFORE UPDATE ON 예시    -- updated_at 자동 갱신
  FOR EACH ROW EXECUTE FUNCTION set_updated_at();
```

파이썬에서는:
- 방금 만든 번호 → `INSERT ... RETURNING 예시_id` 후 `cursor.fetchone()["예시_id"]`
- 있으면 수정 → `ON CONFLICT (키) DO UPDATE SET 컬럼 = EXCLUDED.컬럼`
- 여러 SQL을 한 묶음으로 → `with transaction() as cursor:`

**init SQL은 DB가 비어 있을 때 한 번만 돕니다.** 팀원이 새 SQL 파일을 추가했다면 각자 아래 중 하나를 합니다.
- DB를 새로 만들기 (회원 데이터 삭제됨): `docker compose down -v` → `docker compose up -d`
- 데이터를 남기고 새 파일만: DBeaver에서 그 파일을 열고 **Alt + X** (스크립트 전체 실행)

## 5. 자주 나는 오류

| 증상 | 원인 | 해결 |
|---|---|---|
| `failed to connect to the docker API` | Docker Desktop이 꺼져 있음 | Docker Desktop 켜기 (`Engine running`) |
| `port is already allocated` (5433) | 다른 프로그램이 5433 사용 중 | 그 프로그램을 끄거나 `docker-compose.yml`과 `.env`의 포트를 같이 바꾸기 |
| 백엔드 `password authentication failed for user "admin"` | `.env`가 옛 MySQL 값 그대로 | 1번 ①처럼 `.env` 바꾸기 |
| 백엔드 `relation "users" does not exist` | 테이블이 안 만들어짐 (볼륨이 이미 있어서 init SQL이 안 돌았음) | `docker compose down -v` → `up -d` |
| 백엔드 `connection timeout expired` | DB 컨테이너가 꺼져 있음 | `docker compose up -d` |
| 디스코드 콜백 `Internal Server Error` | 위와 같은 DB 연결 문제 | DB를 켠 뒤 **처음부터 다시 로그인** (콜백 주소 새로고침 X) |
| 로그에 `00X_...sql` 다음 `ERROR:` | SQL 파일 오류 (그 뒤 파일은 실행 안 됨) | 파일을 고친 뒤 `down -v` → `up -d` |
| DBeaver에서 테이블이 안 보임 | `public` 스키마를 안 펼침 | `labbridge → 스키마 → public → 테이블` |
