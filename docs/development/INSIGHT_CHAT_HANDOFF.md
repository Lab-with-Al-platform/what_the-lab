# 인사이트 읽기 보조와 챗봇 연결 검토안

작성일: 2026-10-17. 팀원 협의용이며 API·화면 최종 합의나 챗봇 구현 완료를 의미하지 않는다.

## 현재 완료 범위

정적 글에 `companionSlug`, `glossary`, 섹션 `termIds`, 문단 유형(`body`, `interpretation`, `application`, `caution`)을 추가했다. 기존 일반 문자열 문단도 그대로 지원한다. 실제 챗봇 버튼·입력창·응답 API는 추가하지 않았다.

## 권장 위치

- PC: 닫힌 상태는 `이 글에 질문하기` 진입점. 열면 기존 우측 보조 패널 영역을 활용하며 4열을 만들지 않는다. 답변은 가운데, 입력창은 패널 하단, 글 제목·닫기는 상단에 둔다.
- 본문 폭을 확보할 수 없는 태블릿: 우측 서랍형 패널을 검토한다.
- 모바일: 아래에서 열어 거의 전체 화면까지 확장하는 질문창. 닫을 때 본문 스크롤 위치로 돌아온다. 상시 입력창으로 글이나 목차를 덮지 않는다.
- 닫기·Esc·키보드 포커스 복귀·모바일 키보드·답변 스크롤을 실제로 검증한다. 글을 선택하지 않은 전역 챗봇과 글 전용 질문의 상태를 혼동하지 않는다.

## 담당자 간 합의할 전달 정보

| 정보 | 목적 / 현재 상태 |
|---|---|
| 글 slug와 유형 | 어떤 글에 대한 질문인지 표시. 현재 정적 데이터에서 확인 가능 |
| 글 판본 식별값 | 승인된 어느 버전을 근거로 했는지 고정. 현재 정적 글에는 정식 revision 계약이 없으므로 연결 전 합의 필요 |
| 섹션 ID | 답변에서 해당 근거 문단으로 돌아가는 링크. 현재 sections[].id 사용 가능 |
| 본문과 편집자 노트 유형 | 원문 결과를 편집 의견과 혼동하지 않도록 구별 |
| 선택한 문장 | 선택 문장 질문은 후속 선택 기능. 사용자가 확인한 문장만 전달 |
| 출처와 답변 범위 | 글 내 설명 / 외부 추가 설명을 구분. 외부 자료 사용 여부와 인용 정책 합의 |

자동으로 질문을 전송하거나 페이지 이동 때 이전 글의 질문을 새 글의 것으로 조용히 바꾸지 않는다. 글 전환 시 대화 범위를 명시한다. 클라이언트가 보내는 글 ID·본문을 서버 권한의 근거로 신뢰하지 않는다. 추후 비공개·미승인 글은 서버에서 접근을 검사한다.

## 답변 규칙 제안

1. 기본은 현재 승인된 글과 연결된 근거 범위 안에서 설명한다.
2. 글에서 확인할 수 없으면 확인되지 않았다고 말한다. 편집자 제안을 논문의 검증 결과처럼 말하지 않는다.
3. 외부 자료를 사용한 추가 설명은 별도 표시·출처를 제공한다. 실제 구현 전 검색 권한·비용·보존 정책을 합의한다.
4. 연구 원자료·개인 연락처·비밀번호 입력을 유도하지 않는다. 모델 호출은 서버에서 하며 비밀키를 브라우저로 보내지 않는다.
5. 챗봇 생성 답변은 관리자 승인 본문과 구분한다. 답변을 승인 글에 자동 반영하거나 게시하지 않는다.

## 이번 작업의 종료 경계

MatterGen 두 글과 용어/편집자 노트 UI를 검증해 인계한다. 로그인·관리자·DB 통합·챗봇 실제 구현은 담당자 합의 후 별도 작업이다.
