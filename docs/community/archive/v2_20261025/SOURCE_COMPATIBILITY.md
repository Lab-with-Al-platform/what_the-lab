## DB 적용 순서의 호환 경계

최신 head는 `20261025_06`입니다. 원본의 `20261022_04` 다음에는 05→06, V1의 `20261024_05` 다음에는 06만 적용합니다. 이전 이력이나 Docker init만 실행한 DB는 먼저 기존 회원·인사이트 이력을 담당자와 대조해야 합니다. 자동 `stamp`, 초기화, 기존 표 삭제를 권하지 않습니다.

원본의 `app.supabase_setup`·`app.insight_*_setup`는 각자 특정 과거 revision에서만 동작하도록 설계된 일회성 적용 도구입니다. 새 head에서 이 과거 도구를 재실행해 실패한다고 게시판 이력을 되돌리거나 버전 번호를 임의 변경하면 안 됩니다. 새 변경은 공통 Alembic 이력으로 올립니다.

## 운영과 프론트엔드 경계

실제 출시에는 같은 사이트의 HTTPS API 프록시를 권장하는 구현 선택을 제공합니다. 프론트/백엔드를 서로 다른 사이트로 배포하면 기존 SameSite=Lax 쿠키와 Discord callback을 포함해 팀 인증 설계를 검증해야 합니다. 제공한 로컬 환경의 통과를 실제 OAuth·Supabase·모바일 기기의 검증으로 확대하지 않습니다.

긴 글의 자동 임시 저장은 개인정보를 브라우저 저장소에 남기지 않기 위해 넣지 않았습니다. 폼 안의 나가기·내부 링크·새로고침에는 유실 경고를 제공하고, 브라우저 뒤로가기 전체 차단은 보장하지 않습니다.
