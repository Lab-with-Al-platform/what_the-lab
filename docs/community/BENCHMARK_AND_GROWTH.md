# 게시판 벤치마크와 참여 전략

조사일: 2026-10-24. 공식 문서·공식 서비스 화면을 직접 확인했습니다. 공개 접근이 가능한 자료를 사용했으며, 각 서비스의 비공개 운영 지표나 카페 회원 전용 자료는 확인하지 않았습니다. 아래의 효과는 검증할 가설이며 유입 증가를 보장하는 수치가 아닙니다.

## 비교에서 채택한 것

UI와 콘텐츠를 복제한 것이 아니라 확인한 사용 패턴을 프로젝트의 연구·개발 맥락에 맞게 해석했습니다. 서비스 원문에 나온 실제 회원 이름·게시글을 샘플 회원이나 초기 콘텐츠로 복사하지 않았습니다.

## 우리 서비스에 맞춘 차별화

### 1. 읽던 사례의 맥락을 질문에 함께 가져오기 — 구현

AI 기술 이름을 모르더라도 ‘이 사례를 내 연구에 적용할 수 있을까요?’라는 질문을 시작할 수 있게 합니다. 공개 기사 하단 CTA → 관련 글이 선택된 작성 폼 → 게시글의 원문 링크 → 자유 태그 기반 전문가 탐색으로 이어집니다. 2026-10-26 통합본에서는 이 검색어를 실제 전문가 찾기에 반영합니다. 협업을 원하면 기존 ‘등록한 연구’ 선택 → 협업 요청 → 요청관리 수락 → 별도 시작 절차로 이어집니다. 게시판 대화가 요청·수락을 자동 실행하지 않습니다.

검증할 지표: 사례 하단에서 게시판 글쓰기에 들어온 횟수 대비 실제 공개 질문 등록 비율. 현재 외부 행동 추적이나 분석 이벤트 수집 코드는 추가하지 않았습니다. 초기에는 동의한 테스트 참가자의 과업 관찰로 확인합니다.

### 2. 인기글보다 ‘도움을 기다리는 질문’이 보이게 — 구현

초기 사용자가 적을 때는 조회 수 경쟁보다 첫 답변을 받는 경험이 더 중요하다는 설계 가설입니다. 질문·문의 중 댓글이 없고 해결되지 않은 글을 서버에서 골라 별도 필터로 제공합니다. 개발자는 대형 프로젝트에 들어가기 전 짧은 경험 하나를 나눌 수 있습니다. 공개 글만 대상으로 안내하고 비공개 문의는 관리자 문의함에 남깁니다.

검증할 지표: 공개 질문의 첫 유효 답변 도착 시간, 48시간 이상 미답변 질문 수. 관리자 자기 댓글·단순 자동 인사와 실제 도움 답변을 구분해 수동 집계합니다. 현재 숫자는 화면에 지어 넣지 않습니다.

### 3. 제안이 어떻게 처리되는지 닫힌 고리를 만들기 — 구현

제안자는 ‘어떤 상황이 불편했는지’ 틀을 사용하고, 작성자·관리자는 대화 중 → 확인 중 → 해결됨으로 표시합니다. 사용자가 상태와 관리자 답변을 직접 확인할 수 있습니다. ‘확인 중’은 개발 일정이나 구현을 보장하는 승인 상태가 아닙니다.

검증할 지표: 접수된 공개 제안 대비 관리자가 검토 답변을 남긴 비율, 해결 표시 이후 같은 문제가 다시 신고되는 횟수.

### 4. 개인 문제는 보이지 않게, 반복되는 일반 질문은 쉽게 찾게 — 구현 + 수동 운영

계정 문제는 비공개로 접수하고, 공개해도 되는 반복 질문은 운영자가 별도 FAQ 문장으로 정리합니다. 초기 FAQ는 소스에서 검수하는 18개 정적 문항이었고, 2026-10-31 LAB TRUST 문항 2개가 추가되어 현재 20개입니다. 관리자 자동 게시 기능은 없습니다. 비공개 문의를 FAQ나 챗봇에 자동 반입하지 않습니다. 실제 사례를 공개하고 싶으면 식별 정보를 제거하고 동의를 받은 새 문안으로 작성합니다.

검증할 지표: FAQ를 읽은 테스트 참여자의 문제 해결 여부, 같은 일반 질문의 반복 비율. 전체 문의가 줄었다는 이유만으로 개선으로 판단하지 않고 문의를 포기한 경우도 확인합니다.

## 첫 2주 운영 제안

1. 운영자 본인 이름으로 이용 안내·첫 질문 예시·의견 요청 3개만 실제 작성합니다. 가짜 회원이나 대화를 만들지 않습니다.
2. 기존 파일럿 연구자·개발자에게 공개 질문과 비공개 문의를 각각 수행하도록 과업을 제시합니다. 이 패키지는 초대·이메일·Discord 메시지를 전송하지 않습니다.
3. 하루 한 번 미답변 질문·비공개 문의·신고함을 확인할 담당자를 지정합니다. 담당자가 정해지기 전 빠른 응답을 약속하지 않습니다.
4. 실제 받은 반복 질문만 FAQ에 수동 반영하고, 아직 미연결 기능의 문구를 최신 상태와 대조합니다.
5. 도입 효과를 확인한 뒤에만 게시판 답변의 이메일·Discord 자동 알림, 참여 보상, AI 요약 등을 별도 결정합니다. 현재 가입 숫자를 늘리기 위한 포인트·가짜 인기순위·무인 게시 기능은 없습니다.

## 회의 방향과의 일치

기준 보고서 §10의 ‘초기 사용자 피드백 채널’ 역할을 중심에 두었습니다. §13의 양면 사용자 확보 방향에 맞춰 연구자는 설명하기 쉽게, 개발자는 작은 도움부터 참여하게 만들었습니다. 일정·봇·AI 에이전트·금전 보상은 이 게시판 개발로 구현 범위를 확장하지 않았습니다.
