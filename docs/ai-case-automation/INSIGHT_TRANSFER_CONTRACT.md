# Claude → 인사이트 전송 파일 계약 v1

작성일: 2026-10-28. 상태: **로컬 파일 검사와 내부 반입 로직의 가상 DB 검증까지 구현**. 반입 로직은 웹·CLI·AWS에 연결하지 않았다. 실제 DB 반입·자동 수집·게시 연결은 아직 없다.

상위 운영 원칙은 [클라우드·PR 반입 기준서](INSIGHT_CLOUD_PR_INGESTION_STANDARD.md)를 따른다. 클라우드 정기 수집은 Claude가 맡고, DB 자격증명은 수집 AI에게 전달하지 않는다. 이 문서는 Claude의 예약 기능이나 구독 사용량을 설정하지 않는다.

## 1. 왜 근거 메모와 본문을 함께 보내나

`Draft`는 검토에 필요한 주장·출처·키워드 제안이다. 이것만 전달하면 관리자에게 보일 긴 원고가 짧은 메모로 대체될 수 있다. 따라서 각 항목에 `draft`와 `article`을 모두 필수로 받는다. `article`에는 기존 공개 화면과 같은 본문·용어 풀이·편집자 노트 구조를 사용한다.

형식 통과는 논문 사실·이용 권리·설정 승인·키워드 승인·PR 승인 또는 게시 승인을 뜻하지 않는다. 기존 후보 등록 API에 이 봉투를 그대로 전송하면 안 된다.

## 2. 검사 실행 — 환경변수와 DB 불필요

저장소의 `backend` 폴더에서 PowerShell로 실행한다.

```powershell
.\.venv\Scripts\python.exe -B -m app.insight_transfer insight-transfer-v1.json --root tests/fixtures
```

정상 종료 코드는 `0`, 검사 실패는 `2`다. 성공 결과의 `db_written`, `publication_approved`는 항상 `false`다. 출력은 검사 결과·항목 수·원본 파일 SHA-256이며 입력 원문을 출력하지 않는다. 해시는 같은 파일인지 확인하는 지문이며 승인자의 신원이나 사실성을 증명하지 않는다.

작성 도구에 제공할 정확한 JSON Schema는 아래 명령으로 얻는다. 표보다 실제 스키마가 우선한다.

```powershell
.\.venv\Scripts\python.exe -B -m app.insight_transfer --schema
```

가상 샘플: `backend/tests/fixtures/insight-transfer-v1.json`. **실제 연구도 게시용 글도 아니며** 모델 호출 없이 직접 작성했다. 실제 원고의 저장 경로는 팀 합의 후 정한다. `data/`에는 실제 수집 원고를 넣지 않는다.

## 3. 봉투와 항목

| 위치 | 필드 | 의미 |
|---|---|---|
| 봉투 | `schema_version` | 정확히 `insight_transfer_v1` |
| 봉투 | `bundle_id`, `run_id` | 묶음·회차 식별자. 영문·숫자·하이픈·밑줄, 최대 100자 |
| 봉투 | `generated_at` | 시간대 포함 생성 시각. 예: `2026-10-28T01:00:00+09:00` |
| 봉투 | `settings_version` | 참조한 설정 버전. 실제 승인 여부를 조회하지 않음 |
| 봉투 | `generator` | `tool`, `model`, `prompt_version`. 비밀키·전체 대화·비공개 추론 기록 제외 |
| 봉투 | `items` | 근거 메모와 전체 기사를 가진 1~10개 항목 |
| 항목 | `draft` | 기존 `Draft` 계약. 주장·근거 위치·열람 범위·키워드 제안 포함 |
| 항목 | `article` | 전체 본문. `sections`, `glossary`, `highlights`, `facts` 등 기존 기사 구조 |
| 항목 | `source_published` | 원출처 발표일 `value`와 `precision` |
| 항목 | `source_checked_at` | 시간대 포함 확인 시각. 봉투 생성 시각 이후는 거절 |
| 항목 | `access_notes`, `rights_notes` | 실제 열람 범위·이용 조건·미확인 사항. 각각 최대 2,000자 |

발표일 정밀도는 `day` → `2026-10-28`, `month` → `2026-10`, `year` → `2026`, `unknown` → `null`이다. 날짜가 없다고 생성일로 채우지 않는다. `article.publishedOn`은 화면 표시용 편집 날짜이며 원출처 발표일을 대신하지 않는다.

`article`은 기존 기사 계약을 재사용하되 새 전송의 알 수 없는 필드·섹션 속성은 거절한다. 선택 속성 `institution`, `imageAlt`, `imageCaption`, `sampleNotice`, `featured`, `companionSlug`도 지원한다.

## 4. 검사 조건과 한계

- UTF-8 일반 JSON 한 파일, 최대 2 MiB, 최대 10개 글. 압축·MDX·Python·SQL 등을 실행하지 않는다.
- `--root` 내부 파일만 읽으며 `..`, 심볼릭 링크·Windows junction, `.json` 이외 확장자를 거절한다. 이는 로컬 검사이며 악의적인 사용자가 검사 도중 파일을 바꾸는 환경의 완전한 격리 장치는 아니다.
- JSON 중복 필드, NaN·Infinity, 잘못된 형식·깊이, 알 수 없는 버전·필드를 거절한다.
- `draft`와 `article`의 `slug`, `kind`, 제목·요약·분야·정규화한 원출처 URL/DOI가 같아야 한다. 출처 제목과 기사 제목은 달라도 된다.
- 묶음 안의 `slug`와 같은 원출처의 같은 유형은 중복 불가. **서로 다른 주소의 사례·트렌드 한 쌍은 허용**한다. 오프라인 파일 검사기는 기존 DB와 대조하지 않는다. 내부 반입 시 중복 처리는 6절에 설명한다.
- 본문에서 참조하는 용어 ID는 용어 목록에 있어야 하며 용어 ID는 중복 불가다.
- 초기에는 `image_policy=no_image`, `coverSrc=null`. 삽화는 본문 검토 후 별도 생성·권리 확인한다. `cover`는 기존 화면의 분류 값이며 생성 이미지 파일이 아니다.
- 외부의 `verified`, 점수, 권리 메모, CAP ID는 작성자의 주장·제안이다. 검사기가 실제 검증 상태나 권한을 부여하지 않는다. 실제 반입 단계에서 서버가 미승인 상태로 정규화하고 승인 목록과 다시 대조해야 한다.
- URL 형식만 검사한다. 링크 접속·논문 다운로드·리디렉션 판별·비밀정보 탐지는 수행하지 않는다. 실제 수집기의 접근 통제와 PR 전체 변경 경로 검사는 별도 필요하다.

## 5. Claude에게 전달할 작성 지시

아래 지시와 **현재 Schema·가상 샘플·편집 운영 기준서**를 함께 제공한다. 문서 작성만으로 실제 수집이나 예약 실행을 지시하지 않는다.

> 인사이트 JSON을 insight_transfer_v1 계약에 맞춰 작성한다. 근거 메모 draft와 전체 기사 article을 함께 보존하고 전체 본문을 생략하지 않는다. 출처 사실, 해석, 적용 아이디어, 주의점은 구분하고 어려운 용어는 풀어 쓴다. 논문을 읽지 못했다면 열람·검증 완료로 적지 않는다. 발표일 미상은 null/unknown이다. 설정 버전을 명시하되 권한을 스스로 승인하지 않는다. CAP ID는 제안이며 새 ID를 임의 생성하지 않는다. 이미지 없이 전달하고 비밀키·개인정보·실행 코드·전체 대화·비공개 추론 기록은 포함하지 않는다. 오프라인 형식 검사에는 DB 정보가 필요하지 않다. PR 머지는 게시 승인이 아니다. 자료나 사용량이 부족하면 보고하고 무한 재시도하거나 유료 사용량을 추가하지 않는다.

## 6. 내부 반입 로직 — 가상 DB 검증 완료 범위

`backend/app/insights/transfer_staging.py`의 `stage_transfer_candidates(session, raw, actor, dry_run=True)`는 기존 importer와 원고 판본 생성을 연결한다. 현재 테스트에서만 호출하며 실행 명령·웹 API는 제공하지 않는다. 호출자는 권한 검사를 마친 신뢰하는 코드여야 하며 바깥 트랜잭션을 먼저 시작해야 한다.

- 기본은 미리 보기로 어떤 자료도 저장하지 않는다. 명시적 저장 시 새 후보만 미승인 전체 원고로 준비한다.
- 근거 메모의 `verified`·점수·서지 확인·접근 수준을 초기화하고 승인된 CAP만 제안값으로 남긴다. 승인·게시 함수는 호출하지 않는다.
- 전체 본문·용어·편집자 문단을 별도 판본으로 보존한다. 출처 URL/DOI의 표기 차이는 정규화한 메모 값을 재사용한다.
- 메모와 원고는 SAVEPOINT로 묶는다. 뒤쪽 글 저장이 실패하면 이번 묶음만 되돌리고, 바깥 작업은 보존한다. 최종 commit은 호출자 책임이며 반입 함수가 임의로 확정하지 않는다.
- 기존 출처의 후보는 재입력해도 전체 원고·관리자 수정·검토 상태·공개본을 바꾸지 않는다. 다른 출처가 이미 사용한 전체 원고 주소를 가져오면 충돌로 거절한다.
- 새 원고 판본의 `transfer`에 회차·설정·작성 도구·발표일 정밀도·열람/권리 메모를 **미검증 제출 정보**로 남긴다. 해시만 함수가 원본 바이트에서 계산한다. 이 메타데이터는 승인 증거가 아니다.

이 검증은 임시 SQLite에서 수행했다. 실제 PostgreSQL 동시 실행이나 인증 경계의 검증을 대신하지 않는다. SQLite 테스트는 명시적 BEGIN 설정으로 SAVEPOINT와 바깥 rollback을 검사한다. 실제 서버·DB 설정은 변경하지 않았다.

가상 DB 테스트만 직접 실행하려면 `backend`에서 다음 명령을 사용한다. `.env`를 바꾸거나 Supabase·Docker를 실행할 필요가 없다.

```powershell
.\.venv\Scripts\python.exe -B -m pytest tests/test_insight_transfer_staging.py -q -p no:cacheprovider
```

2026-10-28 검증 결과: 새 반입 테스트 11개 통과. 전송 검사·기존 후보/편집/workspace/API·오프라인 SQL을 포함한 관련 회귀는 **162 passed, 1 skipped**. 링크 생성 권한 부족으로 1개 건너뛰었고 기존 TestClient deprecation 경고 1개가 있다. 전체 저장소·운영 배포 검증 결과는 아니다. 상세 명령 범위는 [팀 공유용 검증 기록](../qa/INSIGHT_TRANSFER_VERIFICATION_2026-10-28.md)에 기록했다.

## 7. 다음 단계 — 묶음 접수 이력과 신뢰 경계

**현재는 후보의 중복 방지까지이며, 전송 묶음의 영속적 접수·중복 처리 완료는 아니다.** 같은 파일 재입력 시 기존 후보는 보존하지만, 같은 `bundle_id`에 다른 새 출처를 넣은 파일을 묶음 단위로 거절하는 기능은 아직 없다. 모든 항목이 기존 후보인 경우 접수 기록도 새로 만들지 않는다. 따라서 이 함수를 정기 worker나 외부 실행 경로에 바로 연결하지 않는다.

1. 접수 이력 테이블 등으로 묶음 ID·원본 해시·결과를 원고와 함께 저장하는 설계를 확정한다. 같은 ID의 다른 내용·동시 실행·전부 기존 글인 묶음도 테스트해야 한다. 새로운 DB 제약·이력이 필요하며 이번에는 만들거나 적용하지 않았다.
2. 신뢰하는 실행기가 얻은 저장소·PR·커밋·해시를 제출자의 자칭 정보와 구분한다. 현재 봉투에는 PR 승인 필드가 없다. 저장 전 승인 설정 버전·출처 허용 목록도 대조해야 한다.
3. 기계 호출 권한·최소 권한을 설계한다. 이 내부 함수의 actor 인자는 인증 수단이 아니다. 관리자 쿠키를 외부 실행기에 복사하지 않는다.
4. PostgreSQL 동시성·전체 접수 이력의 원자성·외부 인증 검증을 마친 뒤 실제 DB 적용은 별도 권한·변경 범위 확인을 거친다.

기계 인증·IAM, GitHub 보호 규칙·OIDC, AWS 배포, 공개 화면 DB 연결, 트렌드 승인 정책, 정기 실행은 이번 계약 구현의 완료 조건에 포함하지 않는다.
