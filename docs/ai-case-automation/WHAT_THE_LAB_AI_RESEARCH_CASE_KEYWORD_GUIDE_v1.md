# WHAT THE LAB --- AI 접목 연구사례 서칭 및 기술 키워드 추출 가이드 v1

> **목적:** Gemini가 실제 AI 접목 연구사례를 조사하고, WHAT THE LAB의 AI
> 전문가 검색에 사용할 기술 키워드 후보를 실제 사례에서 Bottom-up
> 방식으로 추출하기 위한 작업 지시서입니다.\
> **기준:** 2026-10-06 강사 2차 피드백 이후의 축소된 MVP 방향입니다.

## 1. 현재 WHAT THE LAB의 MVP 방향

WHAT THE LAB은 현재 프로젝트 등록·탐색, 지원/협업요청, 일정, Task Board,
평가 등 큰 협업관리 기능을 MVP에서 우선 제외하고 있습니다.

현재 해결하려는 핵심 문제는 다음과 같습니다.

> **AI를 잘 모르는 연구자는 자신의 연구에 AI를 어디에 적용할 수 있는지,
> 어떤 AI 기술이 필요한지, 어떤 AI 전문가를 찾아야 하는지 알기 어렵다.**

따라서 현재 제품의 핵심은 단순한 AI 전문가 검색이 아니라 다음
흐름입니다.

``` text
실제 AI 접목 연구사례
→ 연구자가 AI 활용 가능성을 이해
→ 필요한 AI 기술 키워드 발견
→ 해당 기술을 가진 AI 전문가 탐색
```

현재 제품을 한 문장으로 표현하면:

> **AI를 잘 모르는 연구자가 실제 연구사례를 통해 자신의 연구에 활용할 AI
> 기술을 발견하고, 그 기술을 가진 AI 전문가를 찾을 수 있도록 돕는
> 플랫폼**

## 2. 핵심 User Flow

``` text
로그인 / 최소 회원가입
        ↓
       메인
        ↓
연구 협업 사례 / AI 트렌드
        ↓
   인사이트 리스트
        ↓
   인사이트 상세
        ↓
 추천 AI 기술 키워드
        ↓
   AI 전문가 찾기
        ↓
 전문가 목록 / 상세
```

인사이트 상세에서 보여주는 AI 기술 키워드와 AI 전문가가 가입할 때
선택하는 기술 스택은 **같은 Keyword Master**를 사용해야 합니다.

그래야 연구자가 사례에서 본 키워드로 실제 전문가를 찾을 수 있습니다.

## 3. 가장 중요한 원칙 --- 키워드를 먼저 만들지 않는다

### 잘못된 방식

``` text
일반적인 AI 기술 목록 작성
→ 기술 스택 확정
→ 사례에 태그
```

### 우리가 원하는 방식

``` text
실제 AI 접목 연구사례 수집
→ 원 논문/공식 자료 확인
→ 실제 사용 AI 기술 확인
→ 연구자 관점 활용 목적 파악
→ 키워드 후보 추출
→ 중복·유사어 정규화
→ Keyword Master 후보
→ 사람 검토
→ 확정
```

**논문이나 공식 자료에 없는 기술을 일반 AI 지식으로 추론해서 확정
키워드로 만들지 마세요.**

## 4. 조사 대상

단순한 AI 논문이 아니라 **비-AI 도메인의 실제 연구 문제에 AI가 접목된
사례**를 찾습니다.

가능한 분야: - 생명과학 / 생물정보학 - 의학 / 의료 - 신약개발 - 화학 -
신소재 / 재료과학 - 물리학 - 천문학 - 기계 / 제조 / 로보틱스 - 환경 /
기후 - 에너지 - 농업 / 식품 - 지구과학 - 기타 기초과학·공학

초기에는 한 분야에 편중되지 않도록 **15\~20개의 검증 가능한 대표
사례**를 수집합니다.

최신성보다 다음을 우선합니다. 1. 실제 연구 문제가 명확한가? 2. AI가 연구
병목 해결에 기여했는가? 3. 연구자와 AI의 역할을 구분할 수 있는가? 4.
실제 결과 또는 적절한 도메인 검증이 있는가? 5. 다른 연구자가 자신의
연구에 적용점을 찾을 수 있는가? 6. 실제 사용 AI 기술을 원 출처에서
확인할 수 있는가?

## 5. Source Pool과 출처 우선순위

### A. 최종 Fact 근거

-   원 논문 / DOI
-   학술지 원문
-   대학·연구기관 공식 프로젝트 페이지
-   연구팀 공식 발표
-   공식 프로젝트/코드 저장소(기술 확인 보조)

### B. 사례 발굴

-   Microsoft Research --- AI for Science
-   Google DeepMind --- Science / Research
-   대학·국가연구기관 AI for Science 프로젝트
-   Nature / Science 계열 AI·과학 융합 연구

### C. 후보/기술 탐색 보조

-   Papers with Code
-   AstaBench
-   AI4Science Community
-   NeurIPS / ICML AI for Science 워크숍
-   관련 Benchmark / Dataset 허브

원칙:

> **C에서 발견 → B에서 맥락 파악 → A의 원 논문/공식 자료에서 최종 확인**

뉴스·블로그만으로 사례나 기술 키워드를 확정하지 않습니다. 좋은 사례를
발견하면 반드시 원 논문 또는 공식 연구기관 자료로 역추적합니다.

## 6. 사례 선정 점수

  평가 항목                                         점수
  --------------------------------------------- --------
  비-AI 분야의 실제 연구 문제인가                      2
  AI가 연구 병목 해결에 실질적으로 기여했는가          2
  도메인 연구자와 AI 역할을 구분할 수 있는가           2
  실제 결과 또는 적절한 검증이 존재하는가              2
  다른 연구자가 적용점을 찾을 수 있는가                2
  필요한 데이터 형태를 설명할 수 있는가                1
  AI의 한계/적용 조건을 설명할 수 있는가               1
  **총점**                                        **12**

-   **9\~12점:** 우선 조사/게시 후보
-   **7\~8점:** 추가 조사
-   **0\~6점:** 우선 제외

출처가 부족하면 점수가 높아도 확정하지 않습니다.

## 7. 사례별 Case Sheet

각 사례는 바로 콘텐츠로 쓰지 말고 먼저 아래 구조로 정리합니다.

### 기본 정보

-   Case ID
-   사례 제목
-   연구 분야 / 세부 분야
-   연구기관 / 연구팀
-   논문명 / 발표연도
-   DOI
-   원문 URL
-   공식 기관/프로젝트 URL
-   검증 상태: `후보 / 추가 조사 필요 / 검증 완료`

### 연구 문제

-   해결하려던 연구 문제
-   기존 연구 방식
-   기존 방식의 병목: 시간 / 비용 / 반복작업 / 탐색범위 / 정확도 /
    계산량 / 실험횟수 등

### AI 역할

-   연구 과정의 어느 단계에 사용됐는가?
-   실제로 어떤 작업을 수행했는가?
-   기존 방식과 무엇이 달라졌는가?

### 실제 사용 AI 기술

각 기술별: - 원문 기술명 - 연구에서의 역할 - 확인 출처 - 가능하면 논문
Section / Methods 위치 - 확인 상태: `직접 확인 / 명시적 근거 부족`

### 연구자 역할

문제 정의 / 가설 설정 / 데이터 생성·선정 / 라벨링 / 실험 설계 / 결과
해석 / 실제 검증 등

### 데이터

-   입력 데이터 종류와 형태
-   데이터 규모(원문에 있을 때만)
-   라벨 유무
-   공개 데이터 여부
-   연구자가 생성한 데이터인지
-   전처리 여부

### 검증

연구 분야에 맞는 검증 방식을 기록합니다. - 생명과학: Wet-lab - 의학:
임상/외부 데이터 - 재료: 실제 합성·물성 측정 - 천문: 관측 데이터 - 기후:
관측/과거 데이터 - 공학: 실험 장치/현장 테스트 - 계산 연구: 독립 Dataset
/ Simulation / Benchmark 등

모든 분야에 Wet-lab을 강제하지 않습니다.

### 성과와 한계

-   원문에서 확인된 결과만 기록
-   수치가 있다면 반드시 원문 확인
-   논문이 밝힌 한계
-   일반화/데이터/적용 조건

## 8. 키워드는 두 층으로 추출

### A. 연구자용 활용 키워드

AI를 잘 모르는 연구자가 이해하고 클릭할 수 있는 표현입니다.

예: - 현미경 이미지 분석 - 이미지 분할 - 단백질 구조 예측 - 분자 특성
예측 - 물성 예측 - 신약 후보 탐색 - 시계열 예측 - 이상 탐지 - 문헌
분석 - 실험 조건 최적화

### B. 전문가용 기술 키워드

AI 전문가가 자신의 역량으로 체크할 수 있는 정확한 기술 용어입니다.

예: - Computer Vision - Image Segmentation - U-Net - Graph Neural
Network (GNN) - Transformer - Bayesian Optimization

두 층은 서로 매핑되어야 합니다.

구조 예시:

``` text
연구 문제: 현미경 이미지에서 세포 영역을 자동으로 나누고 싶다
→ 연구자용: 현미경 이미지 분석
→ AI 기술 분야: 컴퓨터 비전
→ 세부 작업: 이미지 분할
→ 전문가 기술: U-Net
```

**위 예시는 구조 설명용이며, U-Net이 실제 사례의 원문에서 확인된
경우에만 Keyword Master 근거로 사용합니다.**

## 9. 키워드 추출 규칙

1.  논문에 없는 기술을 추론해서 확정하지 않는다.
2.  "이 문제라면 보통 YOLO를 쓴다" 같은 추정은 확정 키워드가 아니다.
3.  실제 사용이 확인된 기술과 해석/추정을 구분한다.
4.  너무 세분화된 모델명만 남기지 않는다.
5.  반대로 `AI`, `딥러닝`처럼 지나치게 넓은 단어만 남기지 않는다.
6.  연구자용 활용 목적과 전문가용 기술을 연결한다.
7.  한글/영문/약어/유사어는 하나의 Master Keyword 아래 정규화한다.
8.  사례당 핵심 검색 키워드는 우선 **3\~5개**를 추천한다.
9.  부수적 기술보다 연구 문제 해결에 핵심적으로 기여한 기술을 우선한다.
10. 근거가 약하면 `candidate`로 남기고 확정하지 않는다.

## 10. 기존 AI 기술 표의 상태

이전에 다음 분류를 예시로 논의했습니다.

분류, 수치·결과 예측, 이미지 분석, 객체 탐지, 영역 분할, 영상 분석,
텍스트 분석, 논문·문서 분석, 시계열 예측, 이상 탐지, 패턴/군집 발견,
그래프·관계 분석, 최적화, 실험 조건 탐색, 새로운 후보 생성, 의사결정
최적화, 설명 가능한 AI, 소량 데이터 활용, 멀티모달 분석.

Random Forest, XGBoost, CNN, ViT, YOLO, U-Net, LLM, RAG, GNN, Bayesian
Optimization, VAE, Diffusion, Reinforcement Learning, SHAP, Transfer
Learning 등의 예도 언급했습니다.

**하지만 이것은 실제 연구사례에서 추출해 확정한 Keyword Master가
아닙니다.**

이번 조사에서 실제 사례를 근거로 이 초안을
**검증·수정·통합·삭제·추가**해야 합니다.

## 11. Master Keyword Dictionary

새 키워드를 자동 확정하지 않습니다.

예시 구조:

``` yaml
display_name_ko: 이미지 분할
display_name_en: Image Segmentation
keyword_type: 연구자용 활용 / AI 기술 분야 / 전문가 세부 기술
parent_keyword: 컴퓨터 비전
synonyms:
  - Segmentation
related_keywords:
  - 이미지 분석
  - U-Net
expert_search: true
evidence_cases:
  - CASE-XXX
status: candidate
```

승격 절차:

``` text
실제 사례 발견
→ 기술 원문 확인
→ 키워드 후보
→ 기존 Master와 중복/유사어 검사
→ 기존 키워드 연결 또는 신규 후보
→ 근거 Case 연결
→ 사람 검토
→ verified
```

## 12. 비-AI 연구자용 콘텐츠 원칙

-   **How보다 What/Why:** 모델 수식보다 어떤 연구 병목을 왜 해결했는지
    설명
-   **AI는 도구:** 연구자를 대체하는 마법처럼 표현하지 않음
-   **Pain Point부터 시작:** 기술명보다 연구자의 문제를 먼저 제시
-   **쉬운 설명 → 정확한 용어:** 비유/풀이 뒤 괄호로 정확한 기술명
-   **연구자 역할 강조:** 가설·데이터·실험·해석·검증을 축소하지 않음
-   **과장·의인화 금지:** "AI가 신약을 발명했다" 대신 "후보를 제안했고
    연구진이 검증했다"
-   **데이터 양 일반화 금지:** 적은 데이터로 가능한지는 문제·모델·데이터
    품질에 따라 다름
-   **분야별 적절한 검증:** Wet-lab만 성공 기준으로 쓰지 않음
-   **원문에 없는 숫자 금지:** 시간 단축·정확도·비용 등은 반드시 출처
    확인

## 13. Gemini에게 요청하는 실제 작업

> **비-AI 도메인 연구에 AI가 실제로 접목된 검증 가능한 연구사례
> 15\~20개를 여러 연구 분야에서 찾고, 각 사례의 원 논문/공식 출처를
> 검증한 뒤 WHAT THE LAB의 AI 전문가 검색에 사용할 기술 키워드 후보를
> Bottom-up 방식으로 추출해 주세요.**

작업 순서: 1. 여러 연구 분야에서 사례 후보 수집 2. 원 논문/DOI/공식 기관
자료 역추적 3. 12점 기준으로 적합성 평가 4. 사례별 Case Sheet 작성 5.
Methods/공식 설명에서 실제 사용 AI 기술 확인 6. 연구자용 활용 키워드 /
AI 기술 분야 / 전문가용 기술 키워드 분리 7. 각 기술 키워드의 근거 출처
표시 8. 전체 사례의 중복·유사어 정규화 9. Keyword Master 초안 작성 10.
기존 사례 검증 전 분류체계와 비교

## 15. 절대 하지 말아야 할 것

-   일반 AI 지식으로 기술 목록을 만든 뒤 "사례에서 추출했다"고 표현하지
    않는다.
-   논문에서 확인되지 않은 모델/기법을 사용했다고 추정하지 않는다.
-   뉴스/블로그 하나만으로 연구 성과를 확정하지 않는다.
-   논문에 없는 수치나 효과를 만들지 않는다.
-   AI가 연구 전체를 수행한 것처럼 표현하지 않는다.
-   모든 분야에 Wet-lab 검증을 요구하지 않는다.
-   Small Data면 항상 AI 적용이 가능하다고 일반화하지 않는다.
-   비슷한 의미의 신규 태그를 무제한 생성하지 않는다.
-   논문 제목에 등장했다는 이유만으로 핵심 검색 키워드로 선정하지
    않는다.
-   Benchmark 성능만으로 실제 연구 협업 성공사례라고 판단하지 않는다.

## 16. 최종적으로 답해야 하는 질문

1.  실제 비-AI 연구에서는 어떤 연구 문제에 AI가 사용되고 있는가?
2.  그 문제를 해결하려면 어떤 AI 역량을 가진 사람이 필요한가?
3.  AI를 잘 모르는 연구자는 그 역량을 어떤 쉬운 키워드로 이해할 수
    있는가?
4.  그 쉬운 키워드를 어떤 실제 AI 기술과 연결해야 하는가?
5.  실제 사례 기준으로 WHAT THE LAB의 초기 전문가 기술 스택 체크박스에는
    무엇을 넣어야 하는가?
6.  여러 연구 분야에서 반복되는 공통 핵심 기술은 무엇인가?
7.  특정 연구 분야에만 나타나는 도메인 특화 기술은 무엇인가?

## 17. 최종 원칙

> **WHAT THE LAB의 AI 기술 키워드는 우리가 임의로 나열한 AI 기술 목록이
> 아니다. 실제 연구 현장에서 AI가 접목된 사례를 조사하고, 그 사례에서
> 확인된 기술을 연구자가 이해할 수 있는 언어와 AI 전문가가 사용하는 기술
> 언어로 연결한 검색 체계다.**
