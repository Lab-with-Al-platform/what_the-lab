# 01. 제품 요구사항·범위·수용 기준

## 1. 목표

AI를 잘 모르는 비-AI 분야 연구자가 **실제 AI 접목 연구사례 → 자신의 연구에의 활용 가능성 → 필요 기술 키워드 → 해당 AI 전문가** 순서로 이동할 수 있도록 검증된 콘텐츠를 지속 공급한다. 연구사례 수집 자체나 SEO용 글 양산은 목적이 아니다.

## 2. 범위

**포함**: API 우선 논문 후보 자동 수집, DOI/출처 확인, 구조화 Case Sheet 추출, 12점 평가, 근거 검사, Keyword Master의 기존 키워드 연결/신규 후보 보류, 한국어 비전문가용 요약 초안, 관리자 승인/반려/재분석/예약, 기존 인사이트 공개, 실행·승인 감사 로그.

**제외**: 새 프로젝트/협업 관리 기능, 프로젝트 등록·지원, 일정, Task Board, 계약/결제/평가, 모델 학습/논문 전문 무단 재배포, 자동 키워드 확정, 검증 없는 자동 게시, 웹사이트 전체 스크레이핑.

**콘텐츠 분류(필수)**:
- `applied_research`: 실제 비-AI 연구에 AI 적용이 확인된 논문. 실제 인적/조직간 협업 사실까지 추론하지 않는다.
- `verified_collaboration`: 명시적 공동연구 근거(기관/저자 역할/프로젝트 공식 기록)를 관리자가 검증한 경우.
- `scenario`: 자료집 G절 CASE-LAB-01~05 등의 **가정 시나리오**. 논문 기반 실제 수행 결과처럼 게시하지 않는다. 초기엔 공개 대기/별도 콘텐츠 분류.
- `domestic_reference`: 자료집 국내 사례 15건: DOI·초록 확인으로 표기되어 있으므로 원문 기술 검증 전에는 verified로 간주하지 않는다.

## 3. 페르소나/유저 스토리

| 주체 | 사용자 스토리 | 승인 조건 |
|---|---|---|
| 비-AI 연구자 | 연구 문제와 사례를 읽고 기술 탐색 | 무엇/왜/어떤 데이터/역할/한계/출처 구분 가능 |
| 연구자 | 기술 태그에서 전문가 검색 | 태그는 `verified` Master ID로만 연결 |
| 관리자 | 출처 및 주장 근거 확인 후 게시 | 승인 권한/이력/게시 전 미리보기 |
| 운영자 | 실패 수집을 재시도 | 중복 없이 재개, 알림/로그 |
| AI 전문가 | 동일 키워드로 검색 노출 | 기존 전문가 스택과 Master ID 동일 |

## 5. 핵심 업무 규칙

1. 관리자 승인 전 외부 공개 없음. AI 점수와 출처 메타데이터가 양호해도 자동 승인 없음.
2. 12점 점수: 실제 비-AI 문제(2), 병목 기여(2), 역할 분리(2), 검증 결과(2), 타 연구 활용(2), 입력 데이터(1), 한계/조건(1). `9~12` 우선 후보 / `7~8` 추가 조사 / `0~6` 제외. 출처 부족 시 고득점이어도 보류.
3. 논문에 없는 기술·수치·효과는 확정하지 않음; 초록만으로 Methods 검증 주장 금지.
4. 3~5개 핵심 검색 기술 태그 추천(하드 최대치는 정책/화면 확인 후 결정).
5. 원문/기관 저작권·로봇 정책 준수; 논문 전문과 출판사 그림 무단 복제 금지.
6. 새로운 사례는 공개 ID와 DB PK를 분리하고, 중복 수집에 의해 CASE 번호 증가하지 않도록 한다.

## 6. 비기능 목표(설계 제안, 운영 전 조정)

- 수집 작업 1회 실패가 공개 서비스를 다운시키지 않음.
- 재실행 3회에도 동일 DOI → 후보 1개, 동일 승인 → 게시물 1개.
- 소스 API 실패 시 재시도 후 다음 실행에서 다시 탐색 가능.
- 관리자 외 승인 API 403, 무인 예약 실행은 이전 승인 결과만 발행.
- 비밀키 로그 출력 없음; 생성 텍스트는 구조화 검증·XSS 방지 후 렌더링.
- 사용자 화면은 기존 랜딩/인사이트 상세의 토큰·간격·컴포넌트 사용; 디자인 임의 전면 개편 금지.

## 7. 오픈 질문

기존 스택과 Keyword Master 결정안 미확인, 사용자 정의 승인자 역할·게시 시간대·무료 티어/운영 리소스, 현재 인사이트 콘텐츠 구조, DOI 없는 출처 취급 정책은 `09`에서 확인한다.
