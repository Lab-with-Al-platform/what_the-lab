2. CAP/FIELD/TOOL은 서로 다른 정보예요

CAP — 기술

무엇을 할 수 있나요? 예: 객체 탐지, 시계열 예측

FIELD — 연구 분야

어디에 적용하나요? 예: 생명과학, 사회과학

TOOL — 도구

무엇을 사용하나요? 예: Python, PyTorch

UI GROUP — 화면 메뉴

80개를 다 보여주지 않고 대분류로 묶어 탐색해요.

예: PyTorch를 사용할 줄 안다고 의료영상 분석의 실무 경험이 자동으로 인정되지는 않아요. 연구 분야 경험과 실제 수행 기술도 별도로 관리해야 해요.

4. 개발 패키지 파일들은 어디에 쓰일까?

파일역할연동 주의점
사용자 검색 → 화면에서 CAP/FIELD ID 선택
→ FastAPI 검색 API(미구현/연동 필요)
→ 전문가 프로필의 ID와 비교
→ 공개 전문가 목록 → 상세 보기
→ 요청 API로 협업 요청 저장 → 전문가만 조회

5. 실제 배포 전에 검증해야 할 항목

정적검사 통과가 서비스 운영 승인을 뜻하지는 않습니다. 특히 CAP 80개는 어느 국제기관이 공식 지정한 목록이 아니라, 연구자 의뢰 작업을 기준으로 자체 선정한 목록입니다.

게이트내용현재 상태합격 조건

추천 작업 순서

① 개념 검수 → ② 실제 연구자 표현 검증 → ③ 팀의 API/DB 계약 → ④ 전문성 검증 정책 → ⑤ 검색·상세·요청·수신 E2E → ⑥ 보안·롤백 테스트 → ⑦ 담당자 승인

FIELD의 공식 국가표준 코드는 항목별 매핑을 승인하기 전까지 비워 둡니다. OECD 2015는 현행판이며 한국의 2025 개정 분류와 ANZSRC 2020(2025 정정)을 참고했습니다.

6. 신뢰할 수 있는 자료와 활용 범위

출처를 확인했다는 사실은 각 CAP/FIELD 항목이 국제 공인 코드라는 의미가 아닙니다. 직접 검색 서비스 목적에 맞게 구성한 자체 분류체계입니다.
